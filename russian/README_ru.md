# Арифметическая структура стандартного генетического кода

Этот репозиторий содержит препринт, наборы данных, рисунки
и код воспроизводимости для работы об арифметической
структуре нуклонных величин в группах кодонов стандартного
генетического кода.

В репозитории находятся:

1. **Препринт** в виде исходного кода LaTeX (`main.tex`,
   `references.bib`) и скомпилированного PDF (`main.pdf`).

2. Четыре **рисунка**, сгенерированных при помощи
   `visualization.html` и встроенных в препринт как
   Рисунки 1, 2, 3 и 4.

3. Пять вручную подготовленных **входных наборов
   данных**, описывающих нуклонный состав двадцати
   канонических аминокислот, соответствия кодонов
   стандартного генетического кода, соответствия кодонов
   всех 27 таблиц трансляции NCBI (нумерация 1–33, с
   пропусками), разбиение кодонов на аналитические группы
   и параметрические ключи, используемые для обработки
   стартового и стоп-кодонов.

4. Основной анализ воспроизводится одним самодостаточным
   Python-скриптом `reproduce.py`, который принимает на
   вход пять входных наборов данных и генерирует тринадцать
   вычисленных наборов данных. Скрипт использует только
   стандартную библиотеку Python и производит
   детерминированный, побитово идентичный вывод между
   запусками. Ещё три скрипта — `controls.py`,
   `mc_significance.py` и `verify_mc.py` — добавляют
   вспомогательные контроли специфичности и тест значимости
   (описаны в отдельном разделе ниже) и не входят в
   основной конвейер.

5. Сами тринадцать **вычисленных наборов данных**,
   включённые в репозиторий для тех читателей, которые не
   желают запускать скрипт и хотят просмотреть результаты
   напрямую.

6. Интерактивная **HTML-визуализация** таблицы
   генетического кода и структуры её кодонных групп,
   использовавшаяся на исследовательском этапе работы.
   Она не требуется для воспроизведения ни одного из
   численных результатов, представленных в препринте.

7. Метаданные (`LICENSE`, `LICENSE-CODE`, `CITATION.cff`),
   поддерживающие цитирование и повторное использование
   репозитория.

## Содержимое репозитория

### Исходные файлы препринта

- `main.tex` — исходный код препринта в LaTeX.
- `references.bib` — библиография в формате BibTeX.
- `main.pdf` — скомпилированный препринт.
- `figures/` — рисунки, встроенные в препринт:
  - `codon_table_key0.png` — таблица стандартного
    генетического кода с нуклонными параметрами
    закодированных аминокислот при Key 0. Кодоны Octet I
    (восемь полностью вырожденных семейств) выделены
    фиолетовым; кодоны Octet II — жёлтым. Таблица кодонов
    отображается в порядке C, G, T, A, введённом Румером
    (1968) на химических основаниях — пиримидины и
    пурины чередуются (C, T vs G, A), и внутри каждой
    пары основание с более сильной водородной связью
    предшествует более слабому (C перед T, G перед A).
    Как показано Пановым и Филатовым (2024), это же
    упорядочение — одно из четырёх (из 24 возможных
    перестановок четырёх оснований), в которых Octet I и
    Octet II образуют связные области на матрице кодонов.
  - `sense_pool_structure.png` — нуклонные суммы
    (T, P, N, разность Delta) по смысловому пулу, с
    исключением из сумм трёх стоп-кодонов и инициатора ATG,
    так что каждая показанная величина параметр-независима.
    Рисунок показывает двустороннюю регулярность,
    обсуждаемую в препринте: на осях третьей позиции суммы
    нейтронов лежат на решётке 37, тогда как числа
    водородов Delta лежат на ней или на один атом от неё, а
    суммы протонов (P = N + Delta) следуют из этого.
  - `groups_key0.png` — графический обзор нуклонных
    параметров (T, P, N, Δ) для всех кодонных групп при
    Key 0. Отношения делимости на 37, 111 и 999 выделены
    цветом; перекрёстные равенства между группами
    отмечены красным.
  - `groups_key1.png` — тот же обзор при аналитически
    выведенной параметризации (Key 1). При этой
    параметризации нуклонные параметры четырёх
    32-кодонных групп химических осей (Keto, Strong,
    Amino, Weak) совпадают по T, P, N и Δ.

Все четыре рисунка генерируются файлом `visualization.html`.

### Входные наборы данных

Пять входных наборов данных подготовлены вручную и
составляют полный набор предпосылок, на которых
основываются все вычисленные результаты.

- `amino_acids_nucleons.csv` — целочисленный нуклонный
  состав (протоны, нейтроны, общее число нуклонов,
  разность протонов и нейтронов) двадцати канонических
  аминокислот.
- `genetic_code_codons.csv` — соответствия кодонов
  стандартного генетического кода (таблица трансляции
  NCBI номер 1).
- `ncbi_genetic_code_registry.csv` — соответствия кодонов
  всех 27 таблиц трансляции, поддерживаемых NCBI
  (нумерация 1–33, с пропусками), используемых для
  сравнительного анализа между естественными вариантами
  генетического кода.
- `codon_groups.csv` — определения всех 33 кодонных групп
  (макрогруппы, подгруппы L16 и подгруппы L8),
  используемых в исследовании, вместе с привязками к
  парным группам (twin groups).
- `key_parameters.csv` — параметрические ключи,
  присваивающие нуклонные значения `(P, N)` каждому из
  четырёх служебных кодонов. Key 0 и Key 1 — два ключа,
  проанализированные в препринте; Key 2–Key 9 включены для
  справки и в основном тексте не обсуждаются.

### Вычисленные наборы данных

Все тринадцать вычисленных наборов данных генерируются
скриптом `reproduce.py` из пяти входных наборов данных,
указанных выше.

Наборы данных по ключам (генерируются для каждого из
Key 0 и Key 1):

- `key{N}_nucleon-data.csv` — четыре фундаментальные
  нуклонные величины для каждой из 33 кодонных групп при
  ключе `{N}`.
- `key{N}_divisibility-37.csv` — те же значения,
  выраженные в форме `q*37+r`, чтобы делимость на 37 была
  непосредственно видна.
- `key{N}_equalities.csv` — полное перечисление всех
  численных равенств между нуклонными величинами по
  кодонным группам при ключе `{N}`, классифицированных по
  полю `Match_Type` на `DIFF_PARAM`, `CROSS_PARAM` и
  `SAME_PARAM`.
- `key{N}_ratios.csv` — попарные отношения четырёх
  нуклонных величин для каждой кодонной группы при ключе
  `{N}`, представленные как в точной дробной форме, так и
  в виде десятичного приближения.

Наборы данных, не зависящие от ключа (генерируются
однократно):

- `amino_acids_proton_differences.csv`
- `amino_acids_neutron_differences.csv`
- `amino_acids_nucleon_differences.csv`

Эти три файла перечисляют для каждой пары двадцати
канонических аминокислот абсолютную разность по протонам,
нейтронам и общему числу нуклонов соответственно,
сгруппированную по значению разности.

Сравнительные наборы данных по кодам NCBI:

- `deficit_models_analysis.csv` — применяет тот же
  нуклонный учёт ко всем 27 таблицам трансляции NCBI
  (нумерация 1–33, с пропусками) для поддержки
  сравнительного анализа между стандартным кодом и его
  естественными вариантами.
- `keto_amino_balance_models.csv` — отражает разбиение
  смыслового пула по осям keto/amino (третья позиция G/T
  vs A/C) по нейтронным и протонным счётам, по всем 27
  таблицам трансляции NCBI (нумерация 1–33, с пропусками)
  и при обеих моделях смыслового пула.

Размещённая версия визуализатора доступна по адресу

Страница использует только клиентский JavaScript и может
быть открыта в любом современном браузере без установки,

#### Основные возможности

- **Переключатель таблицы трансляции.** Переключение
  между всеми 27 таблицами трансляции NCBI (нумерация
  1–33, с пропусками), четырьмя дополнительными
  неофициальными кодами (таблицы 34–37) и двумя
  альтернативными параметризациями стандартного кода,
  использующими другие конвенции протонов, нейтронов и
  масс для пролина и глицина. Переключатель открывается
  на стандартном коде по умолчанию.

- **Переключатель пула кодонов.** Переключение между
  полной таблицей из 64 кодонов («ALL CODE») и пулом
  смысловых кодонов элонгации («SENSE CODE»). При
  выбранном «SENSE CODE» служебные кодоны (ATG, TAA,
  TAG, TGA) визуально приглушаются в матрице и
  исключаются из вычислений, предопределённых групп и
  CSV-экспорта; при «ALL CODE» они включены. Поле
  `Code_Section` в экспорте фиксирует, какой режим
  породил файл.

- **Параметрические ключи.** Быстрое переключение между
  нулевой параметризацией (Key 0), симметризацией
  (Key 1) и дополнительными справочными ключами,
  определёнными в `key_parameters.csv`. Пользовательские
  ключи можно создавать, вручную редактируя нуклонные
  вклады, присваиваемые стартовому кодону ATG и каждому
  из трёх стоп-кодонов в отдельности.

- **Редактор аминокислот.** Модальный редактор,
  позволяющий изменять нуклонный состав (протоны,
  нейтроны, масса боковой цепи, масса остова) любой из
  двадцати канонических аминокислот для анализа
  чувствительности или гипотетических конфигураций.

- **Интерактивная матрица кодонов.** 64 кодона
  отображаются в виде матрицы 8×8 из 16 семейств
  кодонов, с покодонными нуклонными значениями,
  выводимыми в реальном времени. Произвольные
  подмножества кодонов могут быть выбраны кликами, что
  позволяет конструировать и анализировать
  пользовательские группы кодонов без написания кода.

- **Динамический калькулятор и расширенный анализ.** Для
  любой выбранной группы кодонов калькулятор вычисляет
  четыре нуклонные величины $P$, $N$, $T$ и $\Delta$,
  проверяет делимость на 37, 111 и 999, отображает все
  попарные отношения этих величин как в виде точных
  дробей, так и в десятичной форме, и представляет
  значения в форме $q \cdot 37 + r$ для прямой визуальной
  проверки делимости. Разворачиваемый раздел «Advanced
  Analysis» раскладывает $\Delta$ по каждому 8-кодонному
  блоку и сообщает структурные дельты между соседними
  подмножествами кодонов.

- **Поиск равенств между множествами.** При изменении
  выделения калькулятор сканирует все предопределённые
  кодонные группы в демонстрационной панели (см. ниже)
  и в реальном времени сообщает о любых численных
  равенствах между нуклонными величинами выбранной
  пользователем группы и любой из предопределённых
  групп. Переключатель области поиска ограничивает поиск
  либо активной вкладкой демонстрации, либо полным
  набором предопределённых групп.

- **Демонстрационная панель.** Коллекция предустановленных
  кодонных групп, организованных в позиционные вкладки
  (Pos 3, Pos 2, Pos 1), каждая из которых представляет
  структурное разбиение по химическому типу нуклеотида в
  соответствующей позиции кодона. Вкладка Pos 3
  соответствует разбиению кодонов на группы,
  использованному в этом исследовании, включая
  макрогруппы, определённые третьим нуклеотидом, и
  разбиение Octet I / Octet II. Дополнительные
  экспериментальные группировки (Quartets, Combinatorial)
  доступны через выпадающее меню; часть из них введена в
  более ранних работах о симметриях генетического кода
  (Shcherbak and Makukov 2013, Panov and Filatov 2024), а
  часть исследована в ходе подготовки настоящей работы,
  при этом более тонкие подразбиения Quartets не
  обсуждаются в препринте. Каждая кнопка предустановки
  отображает нуклонные величины соответствующей группы и
  обновляется при изменении параметрических ключей,
  значений аминокислот или переключателя пула кодонов.
  Академические ссылки на кнопках кликабельны и ведут к
  оригинальным публикациям по DOI.

- **Подсветка симметрий.** Три предопределённые
  перестановки нуклеотидов могут быть применены для
  подсветки связанных кодонов на матрице: преобразование
  Румера $R = (T \leftrightarrow G,\, C \leftrightarrow
  A)$, транзиция $(T \leftrightarrow C,\, A
  \leftrightarrow G)$ и трансверсия $(T \leftrightarrow
  A,\, G \leftrightarrow C)$. Преобразование Румера,
  обсуждаемое в препринте, может быть визуально
  проверено через эту функцию. Независимо от выбранной предустановки, при наведении
  курсора на любой блок кодонов в матрице подсвечивается
  как сам этот блок, так и его образ под текущим активным
  преобразованием, что позволяет интерактивно исследовать
  действие каждой перестановки.

- **Альтернативные представления таблицы кода.** Порядок
  нуклеотидов на осях матрицы можно изменять, генерируя
  альтернативные визуальные представления таблицы
  генетического кода. Все 24 упорядочения доступны через
  эту функцию.

- **Переключатель системы счисления.** Численные
  значения можно отображать в стандартной десятичной
  записи или в системе счисления по основанию 37. В
  системе по основанию 37 число делится на 37 тогда и
  только тогда, когда его представление оканчивается на
  ноль, что позволяет визуально проверять делимость на
  37 для любого отображаемого значения без вычислений.
  Более высокие делимости (например, кратность 111 или
  999) не выделяются дополнительными концевыми нулями и
  остаются обозначенными значками делимости,
  отображаемыми рядом с каждым значением.

- **Разложение в форму Щербака–Макукова.** Для нуклонных
  сумм, кратных 37, калькулятор пытается выразить
  значение в форме $999n + 111m$ — каноническом
  разложении, использованном в исходной работе Щербака
  и Макукова, — и сообщает результат, если такое
  разложение существует.

#### CSV-экспорт

Для активной вкладки демонстрации страница предлагает
четыре независимых CSV-экспорта: **Nucleons** (величины
P, N, T и Δ для каждой группы), **Divisibility** (те же
величины с анализом делимости на 37), **Ratios**
(попарные отношения четырёх величин) и **Equalities**
(перекрёстные численные совпадения, перечисленные
поиском равенств). Отдельный переключатель **области
экспорта** управляет набором столбцов: «Strict»
экспортирует только инвариантные величины (T, P, N, Δ),
тогда как «Full» дополнительно экспортирует компоненты
массы боковой цепи и остова.

Эти функции экспорта предшествуют скрипту
воспроизводимости `reproduce.py` и используют более
раннюю конвенцию форматирования. CSV-файлы,
распространяемые в этом репозитории, создаются скриптом
`reproduce.py` и следуют единым конвенциям формата,
описанным выше. CSV-файлы, экспортированные со страницы
визуализации, могут отличаться от копий из репозитория
по кавычированию, сортировке, окончаниям строк или
содержимому, и не должны использоваться в качестве
замены выходов, сгенерированных скриптом, когда требуется точная воспроизводимость. Следует также учитывать,
что экспорт всегда отражает текущее состояние страницы:
выбранную вкладку позиции (Pos 1, Pos 2, Pos 3, Quartets,
Combinatorial), порядок нуклеотидов на осях, активный ключ,
переключатель пула кодонов и область экспорта. CSV-файлы из
репозитория соответствуют вкладке Pos 3 с порядком осей по
умолчанию; для их воспроизведения со страницы нужна та же
конфигурация. Экспорт из визуализации предоставляется
исключительно для удобства интерактивной исследовательской
работы.

### Вспомогательные контроли

Ещё четыре набора данных проверяют *специфичность* арифметических регулярностей и
производятся отдельным скриптом `controls.py`. Как и `reproduce.py`, он
использует только стандартную библиотеку Python, точную целочисленную арифметику
и не использует рандомизацию, а его выходные файлы следуют тем же конвенциям
формата. Он **не** является частью основного конвейера воспроизводимости: он
читает те же входные наборы данных, но не генерирует ни один из тринадцати
вычисленных наборов данных выше и не требуется для их получения. Подробности и
порядок запуска см. в отдельном разделе ниже.

- `controls.py` — вспомогательный контрольный скрипт.
- `position_axis_analysis.csv` — три химические оси, применённые к первой,
  второй и третьей позиции кодона (при смысловом пуле, Key 0 и Key 1; смысловой пул приводится потому, что, не содержа служебных кодонов, он не зависит от параметрического ключа). Из
  величин групп-осей, делящихся на 37, на третьей позиции — одиннадцать, на

  независимый факт), на второй — ни одной.
- `prime_divisibility_scan.csv` — для каждого простого числа до 97 и для трёх
  наборов значений: сколько групповых величин оно делит, по всем экземплярам,
  по различным значениям и по различным нечётным ядрам. Помимо 2 (чётность
  протонов) и 5 (след регулярности круглых чисел — делимости на 10, 100 и 1000,

  отдельной величины. Это сохраняется даже в наборе значений, где 37 не навязан.
- `position_asymmetry_ncbi.csv` — асимметрия Keto/Amino, вычисленная на смысловом пуле (чтобы таблицы с разными наборами стоп-кодонов оставались сопоставимыми), на всех
  трёх позициях кодона по 27 таблицам трансляции NCBI. Асимметрия делится на 37
  на всех трёх позициях для стандартного кода и его точного эквивалента по

  позиции для любой другой таблицы.
- `representation_sensitivity.csv` — несущие величины смыслового пула,
  пересчитанные при альтернативных молекулярных представлениях
  кодируемой аминокислоты (свободная аминокислота, пептидный остаток,
  цвиттерион); реляционные регулярности (разности Trp/Ile и осевые)

Ещё один скрипт, `mc_significance.py`, оценивает *статистическую значимость*
структуры при нулевой модели случайного кода (случайное переназначение двадцати
аминокислот блокам синонимов). В отличие от `controls.py`, он рандомизирован
(хотя и с фиксированным seed для воспроизводимости). См. отдельный

- `mc_significance.py` — тест значимости методом Монте-Карло.

## Конвенции формата файлов

Все CSV-файлы в этом репозитории следуют одним и тем же
конвенциям:

- Кодировка: UTF-8.
- Разделитель полей: запятая (`,`).
- Кавычивание: все строковые поля заключены в двойные
  кавычки, все числовые поля — без кавычек (эквивалент
  `csv.QUOTE_NONNUMERIC` в Python).
- Разделитель списков внутри поля в кавычках: точка с
  запятой (`;`).
- Окончание строки: LF (`\n`).
- Завершающий перевод строки: каждый файл заканчивается
  одним символом LF.
- Порядок строк: детерминирован внутри каждого файла; см.
  раздел `reproduce.py` для правила сортировки,
  применённого к каждому вычисленному набору данных.

Кодоны представлены в ДНК-нотации с использованием
алфавита `{A, T, G, C}`. Аминокислоты обозначаются
полными названиями, стандартными трёхбуквенными кодами
или однобуквенными кодами IUPAC по уместности.
Стоп-кодоны в однобуквенной нотации обозначаются звёздочкой
(`*`).

64 кодона генетического кода разбиваются на две
структурные половины по 32 кодона каждая:

- **Octet I** — 32 кодона, принадлежащие к восьми
  полностью четырёхкратно вырожденным кодонным семействам
  (GCN, CGN, GGN, CCN, ACN, GTN, CTN, TCN), в которых
  третий нуклеотид не влияет на кодируемую аминокислоту.
- **Octet II** — оставшиеся 32 кодона, принадлежащие к
  кодонным семействам со смешанной или меньшей
  вырожденностью. Все четыре служебных кодона
  стандартного кода (три стоп-сигнала TAA, TAG, TGA и
  стартовый сигнал ATG) принадлежат к Octet II.

Если не указано иное, наборы данных описывают
стандартный генетический код (таблица трансляции NCBI
номер 1). Файлы `ncbi_genetic_code_registry.csv`,
`deficit_models_analysis.csv` и
`keto_amino_balance_models.csv` покрывают все варианты
генетического кода, признанные NCBI (27 таблиц
трансляции, нумерация 1–33, с пропусками).

## Скрипт воспроизводимости `reproduce.py`

Все тринадцать вычисленных наборов данных в этом
репозитории генерируются из пяти входных наборов данных
одним Python-скриптом `reproduce.py`. Скрипт является
авторитетным определением того, как выводятся
вычисленные наборы данных; сами вычисленные наборы
предоставляются для удобства, но могут быть
сгенерированы заново в любой момент.

### Требования

- Python 3.8 или новее.
- Только стандартная библиотека. Внешние пакеты не
  требуются и не используются. В частности, скрипт не
  зависит от `numpy`, `pandas` или любой другой
  сторонней библиотеки и не требует виртуального
  окружения.

### Использование

Запустите скрипт из каталога репозитория:

    python3 reproduce.py

Скрипт читает пять входных CSV-файлов из текущего
каталога и записывает тринадцать вычисленных CSV-файлов
в тот же каталог, перезаписывая любые существующие файлы
с тем же именем. Аргументы командной строки, файлы
конфигурации, переменные окружения и интерактивные
запросы не используются. По успешному завершению скрипт
выводит одну итоговую строку и завершается со статусом 0.

### Детерминированность

Скрипт полностью детерминирован. Запуск его дважды на
одних и тех же входных файлах производит тринадцать
выходных файлов, идентичных побайтно и идентичных между
операционными системами и версиями Python в пределах
поддерживаемого диапазона. Эта детерминированность
достигается тремя свойствами:

1. Вся арифметика выполняется в точной целочисленной
   арифметике, с единственным исключением — десятичных
   приближений в файлах `*_ratios.csv`, которые
   вычисляются из точных рациональных значений и
   округляются до фиксированного числа знаков после
   запятой.
2. Каждая выходная строка производится явным
   детерминированным правилом сортировки (описанным
   ниже), без какой-либо зависимости от порядка
   итерации словарей, упорядочения множеств или
   упорядочения файловой системы.
3. Все выходные файлы записываются с фиксированным
   CSV-диалектом (`csv.QUOTE_NONNUMERIC`, окончания строк
   LF, завершающий перевод строки), независимо от
   платформы хоста.

### Правила сортировки

Каждый вычисленный набор данных использует одно явное
правило сортировки, применяемое единообразно ко всем
строкам файла, без особых случаев:

- `key{N}_nucleon-data.csv`, `key{N}_divisibility-37.csv`,
  `key{N}_ratios.csv` — строки сортируются по `Group_ID`
  по возрастанию (от 1 до 33), что соответствует
  нумерации групп, определённой в `codon_groups.csv`.
- `key{N}_equalities.csv` — строки сортируются прежде
  всего по `Nucleon_Value` по возрастанию, затем по
  `Match_Type` в порядке `DIFF_PARAM`, `CROSS_PARAM`,
  `SAME_PARAM`, затем по `Source_ID` по возрастанию,
  затем по `Target_ID` по возрастанию. Это помещает
  меньшие по величине равенства первыми и, внутри
  каждого значения равенства, сообщает о структурно
  более сильных типах равенства перед более слабыми.
- `amino_acids_proton_differences.csv`,
  `amino_acids_neutron_differences.csv`,
  `amino_acids_nucleon_differences.csv` — строки
  сортируются по значению разности по возрастанию.
  Внутри каждой строки список пар аминокислот
  (хранящийся в столбце `Amino_Acid_Pairs` как
  разделённая точкой с запятой строка) сам по себе
  отсортирован в алфавитном порядке.
- `deficit_models_analysis.csv`,
  `keto_amino_balance_models.csv` — строки сортируются
  по идентификатору таблицы трансляции NCBI по
  возрастанию (от 1 до 33).

### Вход и выход

Скрипт читает следующие входные файлы:

- `amino_acids_nucleons.csv`
- `genetic_code_codons.csv`
- `ncbi_genetic_code_registry.csv`
- `codon_groups.csv`
- `key_parameters.csv`

Скрипт записывает следующие выходные файлы:

- `key0_nucleon-data.csv`, `key1_nucleon-data.csv`
- `key0_divisibility-37.csv`, `key1_divisibility-37.csv`
- `key0_equalities.csv`, `key1_equalities.csv`
- `key0_ratios.csv`, `key1_ratios.csv`
- `amino_acids_proton_differences.csv`
- `amino_acids_neutron_differences.csv`
- `amino_acids_nucleon_differences.csv`
- `deficit_models_analysis.csv`
- `keto_amino_balance_models.csv`

По умолчанию скрипт обрабатывает только Key 0 и Key 1 —
два параметрических ключа, проанализированных в
сопровождающем препринте. Дополнительные ключи (Key 2 –
Key 9) определены в `key_parameters.csv` и могут быть
активированы изменением одной переменной в начале
скрипта; по умолчанию они не включены.

### Верификация

После запуска скрипта читатели, желающие проверить, что
вычисленные наборы данных в репозитории соответствуют
тому, что производит скрипт, могут сравнить заново
записанные файлы с любыми эталонными копиями с помощью
стандартного инструмента сравнения файлов. Поскольку
скрипт детерминирован и использует фиксированный
CSV-диалект, любое отличие между свежесгенерированным
файлом и эталонной копией свидетельствовало бы либо об
изменении скрипта, либо об изменении одного из входных
наборов данных, либо об ошибке, и должно быть
исследовано.

## Вспомогательный контрольный скрипт `controls.py`

`controls.py` — автономный спутник `reproduce.py`, генерирующий четыре
вспомогательных контрольных набора данных. Он не является частью основного
конвейера воспроизводимости и не требуется для воспроизведения какого-либо
численного результата, представленного в препринте; он существует для того,
чтобы проверить, насколько *специфичны* эти результаты для стандартного кода,
для третьей позиции кодона, для модуля 37 и для представления свободных
аминокислот. Третий из контролей при этом
документирует и нетривиальную саму по себе закономерность — асимметрия
Keto/Amino делится на 37 на всех трёх позициях кодона — и показывает, что она
уникальна для стандартного кода (и его близнеца, таблицы 11 NCBI).

### Требования

Python 3, только стандартная библиотека. Внешние пакеты и доступ к сети не
требуются.

### Использование

    python3 controls.py

Скрипт читает входные наборы данных `amino_acids_nucleons.csv`,
`genetic_code_codons.csv`, `codon_groups.csv`, `key_parameters.csv` и
`ncbi_genetic_code_registry.csv` из своего каталога и записывает четыре контрольных
набора данных в тот же каталог.

### Детерминированность

Как и в `reproduce.py`, вся арифметика выполняется в точной целочисленной
арифметике, рандомизация не используется, а вывод воспроизводится побайтно между
запусками. Все количества и остатки — целые числа; единственное ожидаемое
(случайное) значение в `prime_divisibility_scan.csv` хранится как точная
несократимая дробь, а не как десятичное число, так что в вывод не попадают числа
с плавающей запятой.

### Четыре контроля

1. **Позиция кодона** (`position_axis_analysis.csv`). Три химические оси,
   которые в препринте применяются к третьей позиции кодона, применяются вместо
   этого к первой, второй и третьей позиции по очереди, при смысловом пуле,
   Key 0 и Key 1. Структура делимости по модулю 37 проявляется преимущественно
   на третьей позиции; на первой позиции есть лишь изолированная делимость
   нейтронов Keto/Amino, на второй — нет.

2. **Выбор модуля** (`prime_divisibility_scan.csv`). Для каждого простого числа
   до 97 и для трёх наборов значений — групп, не зависящих от параметризации (на
   которые 37 нельзя навязать), Key 0 и Key 1 — скрипт подсчитывает, сколько
   групповых величин делит это число, по всем экземплярам и по различным
   значениям. После малых простых 2 (чётность протонов) и 5 (регулярность
   круглых чисел, которую скан тем самым подтверждает) 37 —
   единственный модуль, делящий неслучайную долю, которая одновременно
   устойчива по трём наборам значений и несводима к иерархии удвоения групп, и
   делает это даже в тех наборах значений, где 37 не навязан.
   Перебор ведётся по простым, а не по всем целым числам, потому что делимость на
   составное сводится к его простым множителям (нового модуля не возникает), а
   высшая степень простого лишь заново оценивает те же значения против меньшего
   случайного уровня. 37 отличается от 2 и 5 по базис-независимым признакам: это
   большее простое (реже на одно попадание), у него нет причины типа чётности, и
   оно встречается ровно в одной степени — ни одна величина не делится на 37², так
   что его избыток не растёт с модулем, в отличие от 5, чьи кратные здесь почти
   все кратны 25.
   Приведение каждой делящейся величины к её нечётному ядру — числу, остающемуся
   после удаления всех множителей двойки (например, 296 = 8·37 имеет нечётное
   ядро 37) — устраняет удвоение, вносимое вложенными группами (группа размера 2k
   имеет вдвое бо́льшие нуклонные суммы, чем её уточнение размера k), так что
   подсчёт различных нечётных ядер (колонка `Divisible_Distinct_OddCores`)
   измеряет, сколько действительно независимых величин делит простое. Это делает
   картину резкой: 37 сохраняет десять различных
   нечётных ядер при Key 0 (и более одного в каждом наборе), тогда как мнимые
   избытки бо́льших простых схлопываются в одно
   ядро каждый — 73 = 2·37−1, отголосок самого модуля, и 61, единичная
   факторизация протонного пула пиримидинов, не связанная с 37.

3. **Асимметрия по позициям в кодах NCBI** (`position_asymmetry_ncbi.csv`). Для
   каждой из 27 таблиц трансляции NCBI асимметрия Keto/Amino смыслового пула
   вычисляется для всех четырёх нуклонных величин на каждой позиции кодона.
   Асимметрия делится на 37 на всех трёх позициях только для стандартного кода и
   его точного эквивалента по соответствию кодонов аминокислотам (таблица 11).
   Поскольку таблицы NCBI эволюционно родственны, а не независимые выборки, это
   свидетельство специфичности среди природных кодов, а не вероятностное
   утверждение.

4. **Соглашение подсчёта** (`representation_sensitivity.csv`). Несущие
   величины смыслового пула пересчитываются при трёх молекулярных
   представлениях кодируемой аминокислоты — нейтральной свободной
   аминокислоте (базовое), пептидном остатке (свободная минус одна
   вода, как в цепи) и цвиттерионе — каждое из которых есть постоянный
   нуклонный сдвиг на остаток. Всякая реляционная величина (разность
   Trp/Ile и осевые разности Keto/Amino и Strong/Weak) инвариантна
   при всех трёх, тогда как абсолютные выравнивания (N(All sense) =
   97·37, дефицит, осевые полупулы) выполняются только для свободной
   аминокислоты: однородный сдвиг (ΔP, ΔN) сохраняет делимость
   нейтронов на 37 лишь при ΔN, кратном 37. Свободная аминокислота
   зафиксирована априори как каноническая идентичность кодируемого
   вида, а не выбрана ради делимости.

### Проверка согласованности

При запуске скрипт проверяет, что построенные им группы осей третьей позиции
воспроизводят соответствующие полнокодовые группы из `codon_groups.csv`, так что
генерируемые группы не могут незаметно разойтись с опубликованным реестром.
Первая и вторая позиции кодона не имеют аналога в `codon_groups.csv` (где
определены только группы третьей позиции) и поэтому строятся напрямую из 64
кодонов.


## Тест значимости методом Монте-Карло `mc_significance.py`

`mc_significance.py` отвечает на вопрос, насколько *невероятна* арифметическая
структура при явной нулевой модели, дополняя детерминированные контроли
специфичности выше. В отличие от детерминированных `reproduce.py` и
`controls.py`, он рандомизирован (хотя и с фиксированным seed).

### Требования

Python 3, только стандартная библиотека. Сторонние пакеты не требуются.

### Использование

    python3 mc_significance.py

Скрипт читает те же входные наборы данных, что и `controls.py`, и записывает
сводную таблицу `mc_significance.csv`.

### Нулевая модель

«Случайный код» того рода, что используется в исследованиях оптимальности
генетического кода. Архитектура стандартного кода фиксирована — 64 кодона,
блоки синонимов с их размерами, три стоп-кодона, разбиение Румера Octet I/II и
химические оси третьей позиции — а случайно только то, какая аминокислота, со
своими фиксированными числами протонов и нейтронов, занимает каждый из двадцати
блоков. Испытание — равномерно случайная перестановка двадцати аминокислот по
двадцати блокам. Модуль 37 взят априори из предшествующей литературы, а
статистики заданы до запуска.

### Воспроизводимость

Скрипт рандомизирован, но с фиксированным seed (по умолчанию seed 0, 1 000 000
испытаний), так что приводимые значения воспроизводятся между запусками.

### Четыре заранее заданные статистики

1. **Два независимых якоря 37** — `N(All sense) = 3589 = 97·37` и
   `T(Octet I) = 3700 = 100·37` оба делятся на 37. Достигается у ≈0,0008
   случайных кодов (независимая оценка (1/37)² ≈ 0,00073).
2. **Насыщенность 37 заголовочного разбиения** — среди четырёх нуклонных величин
   девяти групп Румера/осей (всего пула, шести полупулов осей, двух октетов) —
   число делящихся на 37. Стандартный код набирает 13 из 36 при среднем под
   нулём ≈1,0; ≈4×10⁻⁵ случайных кодов достигают 13 или более.
3. **Тот же подсчёт только по группам, не зависящим от параметризации** (на
   которые 37 нельзя навязать). Стандартный код набирает 14 при среднем ≈2,1;
   ≈0,025 случайных кодов достигают этого. Эти 14 сильно зависимы — одиннадцать
   являются копиями T(Octet I) = 100·37 по октету и его подгруппам из 16 и 8
   кодонов, а три — пиримидиновый Δ-каскад, — так что счёт сводится к ≈2
   независимым фактам, а его p-значение несёт делимость T(Octet I).
   Консервативный вариант.
4. **Концентрация всего множества величин у решётки шага 37** — не сколько
   величин являются точными кратными 37, а насколько близко лежат все они. Для
   каждой из 33 групп при обоих ключах усредняется расстояние каждой ненулевой
   величины T/P/N/Δ до ближайшего кратного 37 (264 значения). Стандартный код
   даёт среднее расстояние ≈5,10 при среднем под нулём ≈9,07; ≈8×10⁻⁴ случайных
   кодов лежат так же близко или ближе. Если исключить точные кратные,
  оставшиеся всё равно дают в среднем ≈7,0 против ≈9,5 при равномерном остатке,
   так что это не переформулировка статистики 2. Эффект сильнее при Key 1 (≈4,64),
   чем при Key 0 (≈5,56), но это сравнение несимметрично относительно нулевой
   модели — стандартный код оценивается под Key 1, выведенным для него, тогда
   как случайные коды используют те же фиксированные значения служебных
   кодонов, — поэтому выигрыш Key 1 не свободен от параметризации. Только под
   Key 0, где делимость на 37 не налагается, стандартный код всё равно даёт
   среднее расстояние ≈5,56 против среднего под нулём ≈9,02, достигаемое у
   ≈2,7×10⁻³ случайных кодов: концентрация присутствует до выведенной
   симметризации Key 1, которая её усиливает, но не создаёт (Key 0 сам по себе
   является назначением значений; свободный от назначений уровень — sense pool). Эта статистика
   является агрегированной формой каскада ±1/±2, описанного по группам в
   препринте. Сводная таблица записывает S4, разбитую по ключу, как S4a
   (только Key 0) и S4b (только Key 1) рядом с объединённой S4; эти две строки
   держат значения служебных кодонов фиксированными в каждом испытании
   (условные диагностики при фиксированном ключе, а не полные переназначения
   в служебных позициях), так что число ≈2,7×10⁻³ воспроизводится из скрипта.

Первая, вторая и четвёртая статистики помещают стандартный код глубоко в хвост;
третья — лишь слабо (p ≈ 0,025, счёт с преобладанием делимости T(Octet I)),
так что вес эффекта — в полном разбиении смыслового пула, а не в
параметр-независимых подгруппах самих по себе. p-значение — это невероятность при данной конкретной
нулевой модели (которая фиксирует архитектуру вырожденности кода и нуклонные
числа аминокислот); это другой вопрос, нежели специфичность среди 27 природных
кодов, и оно не говорит ни о каком биологическом механизме.

### Независимая перепроверка

Поскольку это единственный рандомизированный результат в репозитории, он
сопровождается независимой повторной реализацией `verify_mc.py`, не разделяющей
кода с `mc_significance.py`: она читает входные CSV напрямую, строит кодонные
группы из правил третьей позиции и четырёхкратного вырождения (а не из
`codon_groups.csv`) и использует другие фиксированные значения seed, после чего печатает свои результаты
рядом с `mc_significance.csv`. Два скрипта согласуются по каждой статистике:
хвостовая вероятность S2 — несколько ×10⁻⁵ в обоих; счёт S3 по не зависящим от
параметризации группам равен 14 обоими путями при p ≈ 0,025; среднее расстояние
S4 равно 5,10 обоими путями при p ≈ 8×10⁻⁴; S4a только под Key 0 даёт ≈5,56 при
p ≈ 2,7×10⁻³ в обоих; и S4b перепроверяется так же — что является свидетельством
против ошибки в коде любого из них. Поскольку независимая реализация строит все
33 группы напрямую из правил третьей позиции и октета — включая однобуквенные
подгруппы в Octet I и Octet II и никогда не обращаясь по неуникальному имени
группы — она считает S3 без той ошибки поиска группы, которую в этой одной
статистике допускала ранняя версия `mc_significance.py`, и поймала бы пропущенную
или продублированную группу в любой из реализаций. Наблюдаемые значения, которые
она печатает (N(All sense)=3589, T(Octet I)=3700, числа 13 и 14, среднее
расстояние 5,10), также можно проверить вручную по таблицам препринта.

### amino_acids_nucleons.csv

Этот набор данных представляет целочисленный нуклонный
состав 20 канонических аминокислот.

Значения не являются измеренными молекулярными массами.
Это производные целочисленные величины, вычисленные из
атомного состава с использованием стандартных физических
принципов.

#### Молекулярное представление

Каждая аминокислота представлена как нейтральная
свободная молекула аминокислоты (а не как остаток в
пептидной цепи).

Молекулярная формула каждой аминокислоты следует
стандартным биохимическим источникам.

#### Подсчёт протонов

Число протонов вычисляется как сумма атомных номеров
всех атомов в молекулярной формуле:

P = Σ Zᵢ

где Zᵢ — атомный номер элемента i.

Используемые атомные номера:
- Водород (H): Z = 1
- Углерод (C): Z = 6
- Азот (N): Z = 7
- Кислород (O): Z = 8
- Сера (S): Z = 16

#### Подсчёт нейтронов

Число нейтронов вычисляется в предположении самого
распространённого стабильного изотопа каждого элемента.

Для каждого атома число нейтронов:

Nᵢ = Aᵢ − Zᵢ

где:
- Aᵢ — массовое число самого распространённого
  стабильного изотопа,
- Zᵢ — атомный номер элемента i.

Общее число нейтронов получается суммированием по всем
атомам:

N = Σ (Aᵢ − Zᵢ)

Используемые изотопы:
- H-1
- C-12
- N-14
- O-16
- S-32

#### Общее число нуклонов

Общее число нуклонов определяется как:

T = P + N

Эта величина является целым числом по построению и
отражает общее число нуклонов в молекулярном составе.

#### Дисбаланс протонов и нейтронов

Столбец `Delta_P_N` определяется как:

Δ(P−N) = P − N

Это значение характеризует протон-нейтронную асимметрию
в молекуле аминокислоты.

При используемых здесь предположениях об изотопах
протон-нейтронный дисбаланс возникает исключительно из
атомов водорода, которые вносят один протон и ноль
нейтронов:

Delta_P_N = число_атомов_водорода

#### Столбцы

- `Amino_Acid` — название аминокислоты
- `Total_Nucleons` — общее число нуклонов (P + N)
- `Protons` — общее число протонов
- `Neutrons` — общее число нейтронов
- `Delta_P_N` — разность протонов и нейтронов

код как отображение из кодонов, заданных в ДНК-нотации

#### Столбцы

### amino_acids_neutron_differences.csv

Этот набор данных представляет распределение абсолютных
разностей числа нейтронов между всеми неупорядоченными
парами 20 канонических аминокислот.

Используемые для каждой аминокислоты числа нейтронов
взяты напрямую из `amino_acids_nucleons.csv` и вычислены
при тех же предположениях об изотопах.

#### Построение пар

Набор данных включает все возможные неупорядоченные
попарные сравнения различных аминокислот.

Самопары (A–A) исключены.
Порядок пары не имеет значения: пара A–B считается
идентичной B–A и учитывается один раз.

Для набора из 20 аминокислот общее число уникальных
неупорядоченных пар равно:

C(20, 2) = 20 × 19 / 2 = 190

Все количества пар, представленные в этой таблице,
суммируются в 190.

#### Разность по нейтронам

Для каждой неупорядоченной пары аминокислот (i, j)
разность по нейтронам определяется как:

ΔN = |Nᵢ − Nⱼ|

где Nᵢ и Nⱼ — общие количества нейтронов двух
аминокислот.

По построению возможны только неотрицательные
целочисленные разности.

#### Ограничение по чётности

Чётность числа нейтронов аминокислоты определяется
чётностью её количеств атомов водорода и азота, которые
всегда совпадают (см. `amino_acids_proton_differences.csv`).
Это даёт естественное разбиение 20 аминокислот на две
группы:

- Группа 1 (15 аминокислот): нечётное число H, нечётное
  число N — число нейтронов нечётно, общее число
  нуклонов нечётно.
  Члены: Gly, Ala, Ser, Pro, Val, Thr, Cys, Ile, Leu,
  Asp, Glu, Met, His, Phe, Tyr.

- Группа 2 (5 аминокислот): чётное число H, чётное число
  N — число нейтронов чётно, общее число нуклонов
  чётно.
  Члены: Asn, Gln, Lys, Arg, Trp.

Следствие этого разбиения состоит в том, что разности
нейтронов между двумя аминокислотами из одной группы
всегда чётны, а разности нейтронов между аминокислотами
из разных групп всегда нечётны.

#### Покрытие

Таблица включает все целые значения ΔN от 0 до
наблюдаемого максимума 61. Целые значения, для которых
пары аминокислот не существует, явно перечислены с
Number_of_Pairs = 0 и Amino_Acid_Pairs = "No pairs
found".

Из 62 возможных целых значений в этом диапазоне 47
соответствуют как минимум одной паре аминокислот, и 15
не реализованы никакой парой. Нереализованные значения
распределены неравномерно: их паттерн согласуется с
разбиением по чётности, описанным выше, поскольку
межгрупповые разности (всегда нечётные) и внутригрупповые
разности (всегда чётные) вместе ограничивают, какие
значения достижимы.

#### Вырожденные случаи

Пары с ΔN = 0 соответствуют аминокислотам, имеющим в
точности одинаковое общее число нейтронов, несмотря на
различающийся молекулярный состав.

Такие вырождения возникают естественным образом внутри
набора канонических аминокислот и явно включены в набор
данных как отдельная запись таблицы.

#### Столбцы

- `Neutron_Difference` — абсолютная разность общего числа
  нейтронов (ΔN)
- `Number_Of_Pairs` — число неупорядоченных пар
  аминокислот, демонстрирующих эту разность
- `Amino_Acid_Pairs` — разделённый точкой с запятой
  список пар названий аминокислот, соответствующих данной
  разности по нейтронам, или "No pairs found", если пара
  не существует

Каждая пара аминокислот появляется в таблице ровно один
раз.

Для набора из 20 аминокислот общее число уникальных
неупорядоченных пар равно:

C(20, 2) = 20 × 19 / 2 = 190

Все количества пар, представленные в этой таблице,
суммируются в 190.

#### Разность по протонам

Для каждой неупорядоченной пары аминокислот (i, j)
разность по протонам определяется как:

ΔP = |Pᵢ − Pⱼ|

где Pᵢ и Pⱼ — общие количества протонов двух
аминокислот.

По построению возможны только неотрицательные
целочисленные разности.

#### Ограничение по чётности

Все наблюдаемые разности по протонам чётны; ни одна
неупорядоченная пара аминокислот не демонстрирует
нечётную разность по протонам.

Это следует из структурного свойства набора канонических
аминокислот: все 20 аминокислот имеют чётное общее число
протонов. Это, в свою очередь, отражает молекулярную
архитектуру аминокислот — остов NH₂–CH–COOH в сочетании
с любой стандартной боковой цепью всегда даёт чётную
сумму протонов.

Прямое следствие — ΔP = 37 структурно запрещено для
любой пары канонических аминокислот, поскольку 37
нечётно.

#### Покрытие

Таблица включает все целые значения ΔP от 0 до
наблюдаемого максимума 68. Целые значения, для которых
пары аминокислот не существует, явно перечислены с
Number_of_Pairs = 0 и Amino_Acid_Pairs = "No pairs
found".

Из 69 возможных целых значений в этом диапазоне 30
соответствуют как минимум одной паре аминокислот, и 39
не реализованы никакой парой. Все 39 нереализованных
значений — нечётные целые числа, что согласуется с
ограничением по чётности, описанным выше.

#### Вырожденные случаи

Пары с ΔP = 0 соответствуют аминокислотам, имеющим в
точности одинаковое общее число протонов, несмотря на
различающийся молекулярный состав.

Такие вырождения возникают естественным образом внутри
набора канонических аминокислот и явно включены в набор
данных как отдельная запись таблицы.

#### Столбцы

- `Proton_Difference` — абсолютная разность общего числа
  протонов (ΔP)
- `Number_Of_Pairs` — число неупорядоченных пар
  аминокислот, демонстрирующих эту разность
- `Amino_Acid_Pairs` — разделённый точкой с запятой
  список пар названий аминокислот, соответствующих данной
  разности по протонам, или "No pairs found", если пара
  не существует

Каждая пара аминокислот появляется в таблице ровно один
раз.

#### Построение пар

### codon_groups.csv

Этот набор данных содержит 33 кодонные группы,
используемые в анализе симметрий генетического кода.

Каждая группа представляет подмножество из 64 кодонов
стандартного генетического кода, выбранное в
соответствии со специфическими структурными критериями.

#### Нотация имён групп

Имена групп используют теоретико-множественную нотацию
для указания нуклеотидов, присутствующих в третьей
(wobble) позиции кодонов внутри группы.

Формат: `GroupType: {nucleotides}`

Примеры:
- `ALL: {C, G, A, T}` — кодоны с любым нуклеотидом в
  третьей позиции (все 64 кодона)
- `Keto: {G, T}` — кодоны, заканчивающиеся на G или T
  (keto-основания)
- `{C}` — кодоны, заканчивающиеся только на C

Теоретико-множественная нотация {·} означает, что
порядок не существенен: {G, T} эквивалентно {T, G}.

Группы третьей позиции:
- Keto {G, T} vs Amino {A, C} — химические свойства
  (keto- vs amino-группы)
- Strong {C, G} vs Weak {A, T} — сила водородной связи
  (3 vs 2 связи)
- Purine {A, G} vs Pyrimidine {C, T} — структура основания
  (двойное vs одинарное кольцо)

#### Парные группы (twin groups)

Некоторые кодонные группы имеют идентичный
аминокислотный состав, но представлены разными наборами
кодонов. Такие группы называются «парными группами»
(twin groups) и перекрёстно ссылаются через поле
`Twin_Group_ID`.

Парные группы возникают из пиримидиновой синонимии: в
каждом кодонном семействе стандартного генетического
кода кодоны NNC и NNT кодируют одну и ту же
аминокислоту. В результате кодонные группы, отличающиеся
только тем, содержит ли множество нуклеотидов их третьей
позиции C или T, кодируют один и тот же мультимножество
аминокислот. Например, Keto {G,T} и Strong {C,G} —
парные: замена T → C преобразует одно множество в другое,
сохраняя закодированный аминокислотный состав.

Пары парных групп в этом наборе данных:
- Группы 2 ↔ 3: Keto {G,T} ↔ Strong {C,G}
- Группы 4 ↔ 5: Amino {A,C} ↔ Weak {A,T}
- Группы 13 ↔ 14: {G,T} ↔ {C,G} (Octet I)
- Группы 15 ↔ 16: {A,C} ↔ {A,T} (Octet I)
- Группы 24 ↔ 25: {G,T} ↔ {C,G} (Octet II)
- Группы 26 ↔ 27: {A,C} ↔ {A,T} (Octet II)

#### Однонуклеотидные группы {C} и {T}

Однонуклеотидные группы {C} (Group_ID 8, 19, 30) и {T}
(Group_ID 10, 21, 32) кодируют идентичные мультимножества
аминокислот и имеют идентичные нуклонные величины при
любом параметрическом ключе. Это тождество — прямое
следствие пиримидиновой синонимии: кодон, заканчивающийся
на C, и тот же кодон, заканчивающийся на T, по
определению кодируют одну и ту же аминокислоту.

Эти пары не записываются в `Twin_Group_ID`, который
зарезервирован для пар, чей идентичный аминокислотный
состав возникает из пиримидиновой синонимии вдоль
двухнуклеотидной химической оси (Keto/Strong или
Amino/Weak). Ось Purine/Pyrimidine исключена из этого
столбца, потому что Purine содержит все четыре
служебных кодона, тогда как Pyrimidine не содержит ни
одного, так что две группы имеют существенно разный
аминокислотный состав вне Octet I. Пара {C}/{T} также не
является такой парой: она возникает из выбора одного
нуклеотида, а не из химического противопоставления
двухнуклеотидных подмножеств. Тождество {C} и {T}
документировано здесь для полноты.

#### Свойство вырожденности Octet I

Octet I (группы 12–22) состоит целиком из четырёхкратно
вырожденных кодонных семейств, в которых третья (wobble)
позиция не влияет на идентичность аминокислоты. Как
следствие, все группы внутри Octet I, разделяющие один и
тот же паттерн нуклеотидов третьей позиции, кодируют
идентичные мультимножества аминокислот.

В частности:

Группы 13–18 (размер 16 каждая): все шесть групп
кодируют одно и то же мультимножество аминокислот. Эти
группы отличаются только тем, какие два из четырёх
нуклеотидов появляются в третьей позиции.

Группы 19–22 (размер 8 каждая): все четыре группы
кодируют одно и то же мультимножество аминокислот.
Каждая из этих групп содержит кодоны, заканчивающиеся
на один нуклеотид.

Это свойство отличается от «парных групп» (§ Парные
группы), которые возникают из пиримидиновой синонимии и
химической структуры разбиения, а не из вырожденности
самих кодонных семейств.

В Octet II (группы 23–33) это свойство не выполняется,
поскольку Octet II содержит кодонные семейства с
варьирующейся вырожденностью.

Замечание: группы октетов следуют тем же паттернам
разбиения, что и секция All code, ограниченные
кодонами внутри их соответствующих октетов.

#### Столбцы

- `Group_Name` — описательное имя группы
- `Group_ID` — уникальный целочисленный идентификатор
  кодонной группы
- `Twin_Group_ID` — идентификатор парной группы,
  разделяющей идентичный аминокислотный состав, или
  пустая строка, если парной группы не существует
- `Code_Section` — раздел разбиения генетического кода,
  к которому принадлежит группа: «All code» (Group_ID
  1–11), «Octet I» (Group_ID 12–22) или «Octet II»
  (Group_ID 23–33).
- `Group_Size` — число кодонов в группе
- `Codon_List` — разделённый точкой с запятой список
  ДНК-кодонов в группе
- `Amino_Acid_List` — аминокислотная последовательность,
  закодированная кодонной группой, с использованием
  однобуквенной нотации IUPAC; звёздочки (*) обозначают
  стоп-кодоны.

### key_parameters.csv

Этот набор данных определяет десять параметрических
ключей (key0–key9), каждый из которых задаёт нуклонные
значения, присваиваемые четырём служебным кодонам
стандартного генетического кода (стартовому кодону ATG
и трём стоп-кодонам TAA, TAG, TGA). Два из этих ключей,
key0 и key1, проанализированы в сопровождающем
препринте как две основные параметризации; key0 — это
нулевая параметризация, при которой стоп-кодоны вносят
ноль, а ATG трактуется как обычный метионин, а key1 —
симметризация, при которой стоп-кодонам и ATG
присваиваются значения, выведенные аналитически из
условий симметрии. Остальные ключи key2–key9 включены
для справки и в препринте не обсуждаются.

#### Назначение

Каждый набор параметров представляет различную
конфигурацию нуклонных счётов, присваиваемых:
- Стартовому кодону (ATG, кодирующему метионин)
- Стоп-кодонам (TAA, TAG, TGA)

Изменяя эти параметры, анализ проверяет, сохраняются ли
наблюдаемые нуклонные паттерны при различных граничных
условиях генетического кода.

#### Наборы ключей

key0 — **нулевая параметризация**. Стартовому кодону ATG
присваиваются стандартные нуклонные значения метионина;
трём стоп-кодонам присваиваются нулевые нуклонные
значения во всех параметрах. Это эталонная конфигурация,
используемая всякий раз, когда служебные кодоны не
должны вносить вклад в нуклонные суммы.

key1 — **симметризация**. Стартовому кодону ATG
присваивается `(P, N) = (1, 0)`; каждому из трёх
стоп-кодонов присваивается `(P, N) = (37, 37)`. Эти
значения выведены аналитически в препринте как
минимальное неотрицательное целочисленное решение
системы условий симметрии на нуклонные величины по
макрогруппам кодонов.

key2–key9 — дополнительные параметрические ключи, не
проанализированные в основном тексте препринта. Включены
в набор данных для справки и для читателей, желающих
изучить альтернативные конфигурации.

#### Стандартные нуклонные значения

Метионин (продукт стартового кодона ATG):
- Боковая цепь: 75 нуклонов
- Остов: 74 нуклона
- Протоны: 80
- Нейтроны: 69

#### Структура столбцов

Столбцы модификаций (Mod_*):

Целочисленные смещения, применяемые к стандартным
значениям.

Для стартового кодона (ATG):

Final_Value = Standard_Methionine + Mod_Value

Для стоп-кодонов (TAA, TAG, TGA):

Final_Value = 0 + Mod_Value = Mod_Value

(Замечание: в key0 стоп-кодоны имеют Mod_Value = 0, и
поэтому Final_Value = 0)

Столбцы итоговых значений (Final_*):

Результирующие нуклонные счёты, используемые в
вычислениях симметрий.

#### Структура данных

Каждый набор параметров (key0–key9) содержит 4 строки:
- 1 строка для стартового кодона (ATG)
- 3 строки для стоп-кодонов (TAA, TAG, TGA)

Всего: 40 строк данных (10 ключей × 4 кодона)

#### Столбцы

- `Key_ID` — уникальный идентификатор (key0–key9)
- `Codon` — ДНК-кодон (ATG, TAA, TAG или TGA)
- `Mod_Side_Chain` — смещение для нуклонов боковой цепи
- `Mod_Backbone` — смещение для нуклонов остова
- `Mod_Protons` — смещение для числа протонов
- `Mod_Neutrons` — смещение для числа нейтронов
- `Final_Side_Chain` — результирующее число нуклонов
  боковой цепи
- `Final_Backbone` — результирующее число нуклонов
  остова
- `Final_Protons` — результирующее число протонов
- `Final_Neutrons` — результирующее число нейтронов

### ncbi_genetic_code_registry.csv

Этот набор данных перечисляет все варианты генетического
кода, в настоящее время признанные Национальным центром
биотехнологической информации США (NCBI), включая
стандартный код и все известные альтернативные коды.

Данные получены со страницы генетических кодов NCBI
Taxonomy:
https://www.ncbi.nlm.nih.gov/Taxonomy/Utils/wprintgc.cgi

Каждый генетический код идентифицируется номером своей
таблицы трансляции (transl_table), используемым в
аннотациях признаков GenBank и инструментах
биоинформатики.

#### Нумерация таблиц трансляции

Номера таблиц трансляции присваиваются NCBI и не
являются непрерывными. Номера 7, 8, 17, 18, 19 и 20
отсутствуют в текущем реестре: эти записи либо никогда
не присваивались, либо впоследствии были отозваны и
объединены с другими кодами.

#### Формат строки аминокислот

Столбец `Amino_Acids` содержит строку ncbieaa,
определённую NCBI. Это строка из 64 символов, в которой
каждый символ представляет продукт трансляции одного
кодона. Порядок кодонов следует стандартной
NCBI-нумерации: TTT, TTC, TTA, TTG, TCT, TCC, ... (все
64 кодона в порядке T→C→A→G в каждой позиции). Звёздочка
(*) обозначает стоп-кодон, за исключением контекстно-
зависимых кодов (transl_table 27, 28, 31), где вместо
неё используются буквы аминокислот (см. ниже).

#### Бактериальный, архейный и пластидный код растений (transl_table=11)

Этот код идентичен стандартному коду (transl_table=1) в
своих присвоениях аминокислот и стоп-кодонах. Он
перечислен как отдельная запись, потому что бактерии,
археи и пластиды растений используют расширенный набор
стартовых кодонов: в дополнение к ATG, кодоны GTG, TTG,
ATT и CTG могут инициировать трансляцию в этих
организмах.

#### Контекстно-зависимые стоп-кодоны (transl_table=27, 28, 31)

Три кода в этом наборе данных — Karyorelict Nuclear (27),
Condylostoma Nuclear (28) и Blastocrithidia Nuclear (31)
— не содержат звёздочек (*) в своей строке
`Amino_Acids` и имеют `Stop_Context_Dependent`,
установленный в True. Это не ошибка.

Эти коды используют контекстно-зависимое декодирование:
определённые кодоны читаются как аминокислота в середине
белок-кодирующей последовательности и как стоп-сигнал в
конце гена. NCBI записывает букву аминокислоты (Q, W или
E), а не *, в строке ncbieaa, чтобы предотвратить
некорректное усечение белков инструментами трансляции в
этих позициях.

Реальные стоп-кодоны для этих организмов перечислены в
столбце `Stop_Codons` этого набора данных. На исходной
странице NCBI позиции, соответствующие этим кодонам,
отмечены звёздочкой (*) в строке Starts.

#### Столбцы

- `Transl_Table` — номер таблицы трансляции NCBI
- `Code_Name` — полное название генетического кода, как
  дано NCBI
- `Amino_Acids` — 64-символьная строка ncbieaa,
  представляющая продукт трансляции каждого кодона в
  стандартном порядке NCBI; звёздочка (*) обозначает
  стоп-кодон, за исключением контекстно-зависимых кодов
  (transl_table 27, 28, 31), где вместо неё используются
  буквы аминокислот (см. раздел «Контекстно-зависимые
  стоп-кодоны» выше)
- `Stop_Codons` — список кодонов через запятую, которые
  функционируют как стоп-сигналы в этом коде
- `Stop_Context_Dependent` — булев флаг, указывающий,
  использует ли код контекстно-зависимое декодирование
  стоп-кодонов; True для transl_table 27, 28 и 31, False
  для всех остальных кодов

### deficit_models_analysis.csv

Этот набор данных предоставляет сравнительный
арифметический анализ смыслового пула стандартного кода
по всем вариантам генетического кода, признанным NCBI
(27 таблиц трансляции, нумерация 1–33, с пропусками).
Сведены в таблицу два структурно различных теста:

(1) нейтронный дефицит смыслового пула относительно трёх
опорных якорей, выведенных из Octet I (константа 3700,
структурное T(Octet I) и функциональное T(Octet I)). Для
стандартного кода все три дефицита равны 111 = 3·37.

(2) остаток счёта протонов смыслового пула по модулю 37
без отсылки к какому-либо якорю, основанному на Octet I.
Для стандартного кода этот остаток равен −1 ≡ 36 (mod 37)
— это индуцированный чётностью единичный сдвиг,
согласованный со структурной запрещённостью |δP| = 37
для любой пары канонических аминокислот.

Два теста отражают различные аспекты того, как смысловой
пул стандартного кода выравнивается с решёткой по
основанию 37: нейтронный тест — через размерное
сопоставление с масштабом Octet I, протонный тест —
исключительно через анализ остатков.

Этот набор данных генерируется скриптом `reproduce.py`
из `amino_acids_nucleons.csv` и
`ncbi_genetic_code_registry.csv` вместе с остальными
одиннадцатью вычисленными наборами данных в этом
репозитории. Подробности о том, как его перегенерировать,
см. в разделе «Скрипт воспроизводимости `reproduce.py`»
выше.

#### Смысловые кодоны за исключением инициатора ATG

Столбцы `N_Pure` и `Pure_Codons_Count` вычисляются над
множеством смысловых кодонов, за исключением инициатора
ATG. ATG кодирует метионин и является полноценно
функционирующим смысловым кодоном в любой внутренней
позиции; здесь он исключён исключительно в своей роли универсального инициаторного кодона. Все остальные смысловые кодоны,
включая альтернативные стартовые кодоны, такие как GTG и
TTG, сохраняют своё аминокислотное значение во время
элонгации и включены.

Стоп-кодоны берутся из столбца `Stop_Codons` в
`ncbi_genetic_code_registry.csv`, а не выводятся из
строки `Amino_Acids`.

Исключаемые кодоны таким образом:
- все кодоны, перечисленные в столбце `Stop_Codons` для
  каждой таблицы трансляции
- один инициаторный кодон ATG

Таким образом, число кодонов определяется как:

Pure_Codons_Count = 64 − Stop_Count − 1

где Stop_Count — число кодонов, перечисленных в столбце `Stop_Codons`
файла `ncbi_genetic_code_registry.csv` для данной таблицы трансляции.

В обозначениях препринта этот смысловой пул записывается как
`N(All sense)` и `P(All sense)`; столбцы датасетов с суффиксом `_Pure`
(`N_Pure`, `P_Pure`, `N_Keto_Pure`, `P_Amino_Pure` и т. д.)
соответствуют этим величинам смыслового пула. Термин препринта
*смысловые кодоны* (sense codons) обозначает в точности это множество
64 − Stop_Count − 1 (стоп-кодоны и инициатор ATG исключены).

Порядок кодонов, используемый для строки `Amino_Acids`,
следует стандартной нумерации NCBI, описанной в разделе
`ncbi_genetic_code_registry.csv` этого README.

Количества нейтронов для каждой аминокислоты берутся из
`amino_acids_nucleons.csv`.

#### Идентичные значения N_Pure в кодах 1, 11 и 28

Три таблицы трансляции дают одно и то же значение
N_Pure (3589) и тот же дефицит (111). Это следует
непосредственно из методологии выше.

Код 11 (Bacterial, Archaeal and Plant Plastid) имеет
аминокислотное отображение, идентичное стандартному
коду. Поскольку альтернативные стартовые кодоны не
исключаются, его набор смысловых кодонов совпадает с
Кодом 1.

Код 28 (Condylostoma Nuclear) имеет три контекстно-
зависимых стоп-кодона (TAA, TAG, TGA). После того как
эти кодоны исключаются вместе с ATG, результирующий
набор включённых кодонов становится идентичным
множеству, используемому в анализе стандартного кода.

#### Обработка контекстно-зависимых стоп-кодонов (transl_table 27, 28, 31)

Три генетических кода используют контекстно-зависимое
декодирование, где определённые кодоны функционируют как
аминокислоты в середине последовательности и как
стоп-сигналы в конце гена. Для этих кодов оцениваются
две модели.

Модель 1 (`N_Pure`): кодоны, перечисленные в столбце
`Stop_Codons`, исключаются из набора смысловых кодонов,
даже если они кодируют аминокислоту в строке
`Amino_Acids`. Это первичная модель, используемая на
протяжении анализа.

Модель 2 (`N_Pure_Alt`): контекстно-зависимые кодоны
трактуются как смысловые кодоны и включаются, что
согласуется с их элонгационной способностью. Для всех
остальных кодов `N_Pure_Alt` идентично `N_Pure`.

Та же конвенция применяется к протонным столбцам
`P_Pure` и `P_Pure_Alt`.

#### Модели Octet I

В стандартном коде Octet I состоит из 8 полностью
четырёхкратно вырожденных кодонных семейств (32 кодона)
с общим числом нуклонов (протоны + нейтроны), равным
3700. Поскольку альтернативные коды могут переназначать
значения кодонов, оцениваются две модели Octet I.

`Octet1_Struct_T` — общее число нуклонов (протоны +
нейтроны) 32 кодонов, занимающих 8 фиксированных
структурных позиций Octet I (кодонные семейства GC, CG,
GG, CC, AC, GT, CT, TC), независимо от их
аминокислотного присвоения в конкретном коде.

`Octet1_Func_T` — общее число нуклонов (протоны +
нейтроны) всех полностью четырёхкратно вырожденных
кодонных семейств, присутствующих в конкретном коде,
независимо от их положения в таблице кодонов. Кодонное
семейство определяется первыми двумя нуклеотидами
(например, GCN); каждое семейство состоит из четырёх
кодонов, получаемых варьированием третьего нуклеотида
(например, GCT, GCC, GCA, GCG). Семейство считается
четырёхкратно вырожденным, если все четыре его кодона
кодируют одну и ту же аминокислоту и ни один из них не
является стоп-кодоном.

#### Вычисления дефицита

Три значения дефицита вычисляются для оценки
устойчивости соотношения Octet_T − N_Pure = X по всем
кодам, где Octet_T — общее число нуклонов (протоны +
нейтроны) Octet I, а N_Pure — общее число нейтронов
смысловых кодонов за исключением инициатора ATG.

`Deficit_vs_3700` — дефицит против теоретической
константы 3700, равной общему числу нуклонов Octet I в
стандартном коде (3700 − N_Pure).

`Deficit_vs_Struct` — дефицит относительно структурного
общего числа нуклонов Octet I конкретного кода
(Octet1_Struct_T − N_Pure).

`Deficit_vs_Func` — дефицит относительно функционального
общего числа нуклонов Octet I конкретного кода
(Octet1_Func_T − N_Pure).

Те же три дефицита также предоставлены для Модели 2 как
`Deficit_vs_3700_Alt`, `Deficit_vs_Struct_Alt` и
`Deficit_vs_Func_Alt`.

#### Вычисления протонного остатка

В отличие от теста нейтронного дефицита, описанного
выше, тест протонного остатка не использует Octet I. Он
фиксирует остаток смысловокодирующего протонного пула по
модулю 37, вычисляемый напрямую из `P_Pure` (Модель 1)
или `P_Pure_Alt` (Модель 2):

`P_Pure_mod37` = `P_Pure` mod 37
`P_Pure_Alt_mod37` = `P_Pure_Alt` mod 37

Для стандартного кода `P_Pure_mod37` равен 36, что
соответствует −1 по модулю 37 (в наборе данных
записывается неотрицательный представитель класса).
Остаток −1 — это индуцированный чётностью единичный
сдвиг, обсуждаемый в препринте: свойство чётного числа
протонов канонических аминокислот заставляет
локализующую пару Trp/Ile давать |δP| = 36 вместо
решёточного множителя 37, и тот же сдвиг распространяется
на глобальный смысловой пул.

Распределение `P_Pure_mod37` по таблицам NCBI
показывает, какие альтернативные коды сохраняют это
выравнивание −1 mod 37, а какие нет. Как и в случае
теста нейтронного дефицита, результаты в Модели 2
записаны в `P_Pure_Alt_mod37`.

#### Столбцы

- `Transl_Table` — номер таблицы трансляции NCBI
- `Code_Name` — полное название генетического кода, как
  дано NCBI
- `Pure_Codons_Count` — число смысловых кодонов за
  исключением инициатора ATG, в Модели 1 (64 −
  Stop_Count − 1, где Stop_Count включает контекстно-
  зависимые стоп-кодоны для transl_table 27, 28 и 31)
- `Pure_Codons_Count_Alt` — число смысловых кодонов за
  исключением инициатора ATG, в Модели 2; идентично
  `Pure_Codons_Count` для всех кодов, кроме
  transl_table 27, 28 и 31, где оно равно 63
- `N_All` — общее число нейтронов для всех 64 кодонов с
  использованием строки `Amino_Acids` (ncbieaa) из
  `ncbi_genetic_code_registry.csv`; кодоны, явно
  обозначенные звёздочкой (*), вносят ноль; все
  остальные кодоны вносят число нейтронов соответствующей
  аминокислоты, как определено в
  `amino_acids_nucleons.csv`; для контекстно-зависимых
  кодов (transl_table 27, 28, 31) кодоны, функционирующие
  как контекстно-зависимые стопы, представлены своей
  буквой аминокислоты (например, 'Q' или 'W') и вносят
  своё полное число нейтронов
- `N_Pure` — общее число нейтронов смысловых кодонов за
  исключением инициатора ATG (Модель 1: контекстно-
  зависимые стоп-кодоны исключены)
- `N_Pure_Alt` — общее число нейтронов смысловых кодонов

  зависимые стоп-кодоны включены как смысловые кодоны);
  идентично `N_Pure` для всех кодов, кроме transl_table
  27, 28 и 31
- `Octet1_Struct_T` — общее число нуклонов (протоны +
  нейтроны) 8 фиксированных структурных семейств Octet I
- `Octet1_Func_T` — общее число нуклонов (протоны +
  нейтроны) всех четырёхкратно вырожденных семейств в
  конкретном коде
- `Deficit_vs_3700` — дефицит, оцениваемый против
  константы 3700 (Модель 1)
- `Deficit_vs_Struct` — дефицит, оцениваемый против
  структурного общего числа нуклонов Octet I (Модель 1)
- `Deficit_vs_Func` — дефицит, оцениваемый против
  функционального общего числа нуклонов Octet I
  (Модель 1)
- `Deficit_vs_3700_Alt` — дефицит, оцениваемый против
  константы 3700 (Модель 2)
- `Deficit_vs_Struct_Alt` — дефицит, оцениваемый против
  структурного общего числа нуклонов Octet I (Модель 2)
- `Deficit_vs_Func_Alt` — дефицит, оцениваемый против
  функционального общего числа нуклонов Octet I
  (Модель 2)
- `P_All` — общее число протонов для всех 64 кодонов,

- `P_Pure` — общее число протонов смысловых кодонов за

- `P_Pure_Alt` — общее число протонов смысловых кодонов

- `P_Pure_mod37` — остаток `P_Pure` по модулю 37; для

- `P_Pure_Alt_mod37` — остаток `P_Pure_Alt` по модулю 37

### keto_amino_balance_models.csv

Этот набор данных представляет разбиение смыслового пула
по осям keto/amino по всем вариантам генетического кода,
признанным NCBI (27 таблиц трансляции, нумерация 1–33,
с пропусками), как в нейтронных, так и в протонных
величинах, при тех же двух моделях смыслового пула, что
и `deficit_models_analysis.csv`.

Третья позиция кодона разбивает все 64 кодона на две
половины по 32 кодона каждая: половину `Keto` (третья
позиция G или T) и половину `Amino` (третья позиция A
или C). Для каждой таблицы NCBI общие количества
нейтронов и протонов каждой половины вычисляются только
по смысловому пулу — служебные кодоны исключаются из
обеих сумм. В Модели 1 исключаемые служебные кодоны —
все кодоны, перечисленные в столбце `Stop_Codons`, плюс
инициатор ATG; в Модели 2 для таблиц с контекстно-
зависимыми стопами (27, 28, 31) исключается только
инициатор ATG, тогда как для всех остальных таблиц
Модель 2 совпадает с Моделью 1. Это та же конвенция
исключения, что используется в
`deficit_models_analysis.csv`.

Для стандартного кода смысловые keto/amino разности
равны N_Keto − N_Amino = 37 и P_Keto − P_Amino = 36. По
таблицам NCBI эта сигнатура разбивает коды на те, что
сохраняют сигнатуру (37, 36), и те, что её возмущают.

#### Столбцы

- `Transl_Table` — идентификатор таблицы трансляции
  NCBI (1..33, с пропусками)
- `Code_Name` — полное название варианта генетического
  кода
- `N_Keto_Pure` — общее число нейтронов смысловых кодонов
  в половине Keto (третья позиция G или T) в Модели 1
- `N_Amino_Pure` — общее число нейтронов смысловых
  кодонов в половине Amino (третья позиция A или C) в
  Модели 1
- `N_Diff_Pure` — `N_Keto_Pure − N_Amino_Pure` (Модель 1)
- `P_Keto_Pure` — общее число протонов смысловых кодонов
  в половине Keto в Модели 1
- `P_Amino_Pure` — общее число протонов смысловых
  кодонов в половине Amino в Модели 1
- `P_Diff_Pure` — `P_Keto_Pure − P_Amino_Pure` (Модель 1)
- `N_Keto_Pure_Alt`, `N_Amino_Pure_Alt`, `N_Diff_Pure_Alt`,
  `P_Keto_Pure_Alt`, `P_Amino_Pure_Alt`, `P_Diff_Pure_Alt`
  — соответствующие величины в Модели 2; идентичны
  версиям Модели 1 для всех кодов, кроме transl_table
  27, 28 и 31

### key0_nucleon-data.csv и key1_nucleon-data.csv

Это описание применимо к обоим файлам. Оба файла
разделяют одинаковую структуру столбцов; нуклонные
значения различаются между файлами из-за различных
присвоений стартовых и стоп-кодонов, заданных каждым
ключом.

Этот набор данных представляет фундаментальный нуклонный
состав 33 кодонных групп, определённых в
`codon_groups.csv`, вычисленный при параметрической
конфигурации соответствующего ключа.

#### Вычисление

Каждая строка соответствует одной кодонной группе.
Нуклонные значения вычисляются итерированием по всем
кодонам в группе, извлечением строго определённых
параметров эмпирической формулы кодируемой аминокислоты
для каждого кодона и суммированием результатов по
группе.

Вклад стартового кодона (ATG) и стоп-кодонов (TAA, TAG,
TGA) определяется активным ключом. В эталонной
конфигурации (key0) стоп-кодоны вносят ноль во все
нуклонные величины. Альтернативные ключи (например,
key1) присваивают конкретные ненулевые значения
параметров стартовым и/или стоп-кодонам; эти конфигурации
явно определены в исследовании.

#### Нуклонные величины

Для каждой группы представлены четыре строгие,
структурно независимые нуклонные величины:

`Total_Nucleons` — общее число нуклонов, определённое
как:

T = P + N

где P — общее число протонов (сумма атомных номеров всех
атомов), а N — общее число нейтронов (вычисленное для
самых распространённых стабильных изотопов каждого
элемента).

`Delta_P_N` — разность протонов и нейтронов:

Δ = P − N

Это значение численно равно числу атомов водорода в
молекулярном составе, поскольку водород — единственный
элемент в молекулах аминокислот, для которого число
нейтронов равно нулю.

#### Столбцы

- `Group_Name` — описательное имя кодонной группы
- `Group_ID` — уникальный целочисленный идентификатор
  кодонной группы
- `Twin_Group_ID` — идентификатор парной группы,
  разделяющей идентичный аминокислотный состав, или
  пустая строка, если парной группы не существует
- `Code_Section` — раздел разбиения генетического кода,
  к которому принадлежит группа: «All code» (Group_ID
  1–11), «Octet I» (Group_ID 12–22) или «Octet II»
  (Group_ID 23–33)
- `Group_Size` — число кодонов в группе
- `Total_Nucleons` — общее число нуклонов (P + N)
- `Protons` — общее число протонов (P)
- `Neutrons` — общее число нейтронов (N)
- `Delta_P_N` — разность протонов и нейтронов (P − N)

### key0_divisibility-37.csv и key1_divisibility-37.csv

Это описание применимо к обоим файлам. Оба файла

Этот набор данных представляет делимость на 37 четырёх
фундаментальных нуклонных величин для каждой из 33
кодонных групп. Исходные значения берутся напрямую из
соответствующего файла `_nucleon-data.csv` для того же
ключа.

#### Назначение

Набор данных делает структуру делимости нуклонных
величин непосредственно видимой без необходимости
дополнительной арифметики. Вместо хранения сырых
целочисленных значений (которые уже присутствуют в
файлах `_nucleon-data.csv`) каждая ячейка кодирует
результат евклидова деления на 37, позволяя читателю
идентифицировать точную делимость и остаток с одного
взгляда.

#### Формат выражений

Каждая ячейка содержит строковое выражение одной из
следующих форм:

- `q*37` — если значение точно делится на 37, где q —
  целочисленное частное
- `q*37+r` — если значение положительно и не делится на
  37 точно, где q — целочисленное частное, а r — остаток
  (1 ≤ r ≤ 36)

Исключения из этого формата:

- Положительные значения, меньшие 37, записываются как
  простые целые числа.
- Все отрицательные значения записываются как простые
  целые числа во избежание неоднозначности операций по
  модулю над отрицательными числами в разных языках
  программирования.

Исходное нуклонное значение может быть восстановлено из
любого выражения арифметическим вычислением.

- `Group_ID` — уникальный целочисленный идентификатор

  к которому принадлежит группа: «All code» (Group_ID
  1–11), «Octet I» (Group_ID 12–22) или «Octet II»
  (Group_ID 23–33)
- `Group_Size` — число кодонов в группе
- `Total_mod37` — выражение делимости для общего числа

- `Protons_mod37` — выражение делимости для числа
  протонов
- `Neutrons_mod37` — выражение делимости для числа

- `Delta_mod37` — выражение делимости для разности

### key0_equalities.csv и key1_equalities.csv

Это описание применимо к обоим файлам. Оба файла
разделяют одинаковую структуру столбцов; набор
зафиксированных равенств различается между файлами из-за
различных присвоений стартовых и стоп-кодонов, заданных
каждым ключом.

Этот набор данных фиксирует все наблюдаемые численные
равенства между нуклонными величинами по кодонным
группам при параметрической конфигурации соответствующего
ключа. Каждая строка представляет одно равенство:
единственное численное значение, разделяемое исходной и
целевой величинами, принадлежащими двум (возможно,
различным) кодонным группам. Группа может появиться и
как источник, и как цель в одной и той же строке, когда
величина группы равна другой величине той же группы.

#### Типы совпадений

Столбец `Match_Type` классифицирует каждое равенство по
отношению между сравниваемыми параметрами:

- DIFF_PARAM — исходная и целевая группы имеют разные
  размеры (разные уровни), независимо от того, являются
  ли две задействованные нуклонные величины одного типа
  или разных типов (например, число нейтронов группы
  размера 32 равно общему числу нуклонов группы размера
  16).
- CROSS_PARAM — исходная и целевая группы имеют один и
  тот же размер, и две стороны включают разные нуклонные
  величины (например, число протонов группы A равно
  числу нейтронов группы B, где A и B имеют одинаковый
  Group_Size).
- SAME_PARAM — исходная и целевая группы имеют один и
  тот же размер, и обе стороны включают одну и ту же
  нуклонную величину (например, число протонов группы A
  равно числу протонов группы B).

#### Направленность

Источник и цель отражают порядок алгоритмического обхода,
используемый программой при сканировании пар групп. Этот
порядок не основан на величине Group_ID и не подразумевает
направленных или причинных отношений между источником и
целью.

#### Столбцы

- `Nucleon_Value` — общее численное значение равенства
- `Match_Type` — классификация равенства: `SAME_PARAM`,
  `CROSS_PARAM` или `DIFF_PARAM`
- `Source_Section` — раздел кода исходной группы
- `Source_ID` — целочисленный идентификатор исходной
  группы
- `Source_Name` — описательное имя исходной группы
- `Source_Parameter` — нуклонная величина источника
- `Target_Parameter` — нуклонная величина цели
- `Target_Name` — описательное имя целевой группы
- `Target_ID` — целочисленный идентификатор целевой
  группы
- `Target_Section` — раздел кода целевой группы

### prime_divisibility_scan.csv

Вывод `controls.py` (не входит в конвейер `reproduce.py`). Для каждого простого
числа до 97 и для трёх наборов значений файл записывает, сколько нуклонных
величин кодонных групп делит это число, подсчитанных как по всем экземплярам,
так и по различным ненулевым значениям. Три набора значений — это группы, не
зависящие от параметризации (те, что не содержат служебных кодонов и на которые
37 нельзя навязать), все группы при Key 0 и все группы при Key 1; это позволяет
видеть, что 37 доминирует даже там, где оно не навязано параметризацией.
25 простых чисел × 3 набора значений = 75 строк. Сканируются только простые:
делимость на составное сводится к его простым множителям, а высшая степень
простого лишь заново оценивает те же значения против меньшего случайного уровня,
так что простое — неприводимая единица сравнения.

#### Столбцы

- `Value_Set` — `param_independent`, `key0` или `key1`
- `Prime` — проверяемое простое число
- `Divisible_All` — число групповых величин (с учётом каждого экземпляра
  группы), делящихся на это простое число
- `Total_All` — общее число групповых величин в наборе
- `Divisible_Distinct` — число различных ненулевых значений величин, делящихся
  на это простое число
- `Total_Distinct` — общее число различных ненулевых значений величин
- `Expected_Distinct` — ожидание при случайности `Total_Distinct / Prime` числа
  делящихся различных значений при модели равномерных остатков, заданное точной
  несократимой дробью; превышение над случайностью читается как
  `Divisible_Distinct` относительно этого значения
- `Divisible_Distinct_OddCores` — число различных *нечётных ядер* среди
  делящихся различных значений: каждое значение приводится к нечётной части
  (удалением множителей двойки) перед подсчётом. Вложенная иерархия групп
  (Octet I и его 16- и 8-кодонные подгруппы) механически порождает 2V и 4V
  наряду с любой величиной V, так что простое, делящее V, засчитывается до трёх
  раз за один факт; эта колонка устраняет дублирование. По всем наборам 37
  сохраняет десять различных ядер при Key 0 (более одного в каждом наборе),
  тогда как бо́льшие простые выше случайного
  уровня (например 73, 61) схлопываются в одно ядро каждый — 73 = 2·37−1,
  отголосок 37, и 61, единичная факторизация протонного пула пиримидинов.

### representation_sensitivity.csv

Вывод `controls.py` (не входит в конвейер `reproduce.py`). Несущие величины

нейтральной формы, поэтому нуклонные счёты идентичны). Каждое представление —

аминокислоты. Всякая реляционная величина — нейтронная и протонная разности
Trp/Ile и осевые разности Keto/Amino и Strong/Weak — есть разность между наборами
кодонов равной мощности и потому инвариантна при всех трёх представлениях, тогда

делится на 37 только для свободной аминокислоты: однородный сдвиг сохраняет
делимость нейтронов на 37 лишь при ΔN, кратном 37 (60·ΔN ≡ 0 mod 37, gcd(60,37)=1).
При пептидном остатке N(All sense) = 3109 ≡ 1 и P(All sense) = 3580 ≡ 28 (mod 37).
Проверка на этапе сборки не даёт записать файл, если строка свободной аминокислоты
не воспроизводит значения препринта (N = 3589, P = 4180, дефицит = 111,
δN(Trp,Ile) = 37, δP = 36).

- `Representation` — молекулярное представление (`free`, `peptide_residue`, `zwitterion`)
- `Delta_P`, `Delta_N` — протонный и нейтронный сдвиг на остаток относительно свободной аминокислоты
- `Anchor` — вычисляемая величина (например, `N_sense`, `dN_Trp_Ile`, `KetoAmino_dN`)
- `Class` — `absolute` (сумма, зависит от представления) или `relational` (разность между наборами равного размера, инвариантна)
- `Value` — целое значение якоря при данном представлении
- `Value_mod37` — значение по модулю 37 (0 означает делимость на 37)
- `Matches_Free` — совпадает ли со значением свободной аминокислоты; True для всякого реляционного якоря и всех якорей цвиттериона, False для абсолютных якорей пептидного остатка

моделью и эмпирическое p-значение из перестановочной нулевой модели случайного
кода. 6 строк.

#### Столбцы

- `Statistic` — `S1`, `S2`, `S3`, `S4`, `S4a` или `S4b`
- `Description` — что подсчитывает статистика
- `Observed` — значение для стандартного кода (число; для S1 — «both divisible»)
- `Null_Mean` — среднее статистики по случайным кодам (для S1 — доля делящихся)
- `P_Value` — эмпирическая вероятность того, что случайный код не уступает
  стандартному (для S1 — вероятность того, что оба якоря делятся на 37)
- `N_Trials` — число разыгранных случайных кодов
- `Seed` — использованный seed (фиксированный, для воспроизводимости)
