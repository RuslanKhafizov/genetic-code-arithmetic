# Arithmetic structure of the standard genetic code

This repository contains the preprint, datasets, figures, and
reproducibility code for the work on arithmetic structure of
nucleon quantities across codon groups of the standard genetic
code.

It provides:

1. The **preprint** in LaTeX source (`main.tex`,
   `references.bib`) and compiled PDF (`main.pdf`).

2. Four **figures** generated by `visualization.html` and
   embedded in the preprint as Figures 1, 2, 3, and 4.

3. Five hand-curated **input datasets** describing the
   nucleon composition of the twenty canonical amino
   acids, the codon assignments of the standard genetic
   code, the codon assignments of all 27 NCBI translation
   tables (numbered 1–33, with gaps), the partitioning of
   codons into analytical groups, and the parametric keys
   used to handle start and stop codons.

4. The core analysis is reproduced by one self-contained
   Python script, `reproduce.py`, that consumes the five
   input datasets and generates eighteen computed
   datasets. The script uses only the Python standard
   library and produces deterministic, bit-for-bit
   identical output across runs. Five further scripts —
   `controls.py`, `mc_significance.py`, `verify_mc.py`,
   `mc_sensitivity.py`, and `verify_mc_sensitivity.py`
   — add supplementary specificity controls and a
   significance test (described in their own section
   below) and are not part of the core pipeline.

5. The eighteen **computed datasets** themselves,
   provided in the repository so that readers who do not
   wish to run the script can inspect the results
   directly.

6. An interactive **HTML visualization** of the genetic
   code table and its codon-group structure, used during
   the exploratory phase of the study. It is not required
   for reproducing any numerical result reported in the
   preprint.

7. Metadata files (`LICENSE`, `LICENSE-CODE`,
   `CITATION.cff`) supporting citation and reuse of the
   repository.

8. **Russian-language companion materials** under
   `russian/`: the Russian manuscript source (`main_ru.tex`),
   its compiled PDF (`main_ru.pdf`), and a
   Russian-language repository guide (`README_ru.md`).

### Preprint source files

- `main.tex` — LaTeX source of the preprint.
- `references.bib` — BibTeX bibliography.
- `main.pdf` — compiled preprint.
- `russian/` — Russian-language companion materials:
  - `russian/main_ru.tex` — source of the Russian manuscript;
  - `russian/main_ru.pdf` — compiled Russian version of the
    manuscript;
  - `russian/README_ru.md` — Russian-language repository
    guide.
- `figures/` — figures embedded in the preprint:
  - `codon_table_key0.png` — the standard genetic code
    table with nucleon parameters of the encoded amino
    acids under Key 0. Octet I codons (eight four-fold
    degenerate families) are shaded purple; Octet II
    codons are shaded yellow. The codon table is displayed in the C, G, T, A ordering
    introduced by Rumer (1968) on chemical grounds — pyrimidines
    and purines alternate (C, T vs G, A), and within each pair
    the stronger hydrogen-bond partner precedes the weaker (C
    before T, G before A). As shown by Panov and Filatov (2024),
    this same ordering is one of four (out of 24 possible
    permutations of the four bases) in which Octet I and Octet II
    form connected regions on the codon matrix.
  - `pool60_structure.png` — nucleon sums (T, P, N, the
    difference Delta) over the 60-codon service-codon-excluded
    pool (POOL60). The three stop codons and the initiator ATG
    are excluded from the sums, so every quantity shown is
    parametrization-independent. The figure displays the
    two-sided regularity discussed in the preprint: on the
    third-position axes the neutron sums lie on the
    37-lattice while the hydrogen counts Delta lie on it or
    one atom away, and the proton sums (P = N + Delta)
    follow accordingly.
  - `groups_key0.png` — graphical overview of nucleon
    parameters (T, P, N, Δ) for all codon groups under
    Key 0. Divisibility relations by 37, 111 and 999 are
    highlighted in color; cross-group equalities are
    highlighted in red.
  - `groups_key1.png` — the same overview under the
    analytically derived parametrization (Key 1). Under
    this parametrization the nucleon parameters of the
    four chemical-axis 32-codon groups (Keto, Strong,
    Amino, Weak) coincide in T, P, N, and Δ.

All four figures are generated by `visualization.html`.

### Input datasets

The five input datasets are curated by hand and constitute the
complete set of assumptions on which all computed results depend.

- `amino_acids_nucleons.csv` — integer nucleon composition
  (protons, neutrons, total nucleons, proton–neutron difference)
  of the twenty canonical amino acids.
- `genetic_code_codons.csv` — codon assignments of the standard
  genetic code (NCBI translation table 1).
- `ncbi_genetic_code_registry.csv` — codon assignments of all 27
  translation tables maintained by NCBI (numbered 1–33, with gaps),
  used for the comparative analysis across natural genetic code
  variants.
- `codon_groups.csv` — definitions of all 33 codon groups
  (macro-groups, L16 sub-groups and L8 sub-groups) used in the
  study, together with twin-group assignments.
- `key_parameters.csv` — parametric keys assigning nucleon values
  `(P, N)` to each of the four service codons. Keys 0 and 1 are
  the two keys analyzed in the preprint; Keys 2–9 are included
  for reference and are not discussed in the main text.

### Computed datasets

All eighteen computed datasets are generated by `reproduce.py` from
the five input datasets above.

Datasets for the 60-codon service-codon-excluded pool (generated once
for the standard code):

- `pool60_nucleon-data.csv` — the four fundamental nucleon quantities
  for each of the 33 groups after removing ATG, TAA, TAG, and TGA.
- `pool60_divisibility-37.csv` — the same values expressed in the form
  `q*37+r`.
- `pool60_equalities.csv` — complete enumeration of the numerical
  equalities between group quantities at this level.
- `pool60_ratios.csv` — exact and decimal pairwise ratios of the four
  nucleon quantities.

In these files the four service codons are removed from every group,
not retained as zero-valued codons. Consequently, `Group_Size` records
the size of each group after exclusion.

Per-key datasets (generated for each of Key 0 and Key 1):

- `key{N}_nucleon-data.csv` — the four fundamental nucleon
  quantities for each of the 33 codon groups under key `{N}`.
- `key{N}_divisibility-37.csv` — the same values expressed in
  the form `q*37+r` to make divisibility by 37 immediately visible.
- `key{N}_equalities.csv` — complete enumeration of all numerical
  equalities between nucleon quantities across codon groups under
  key `{N}`, classified by `Match_Type` into `DIFF_PARAM`,
  `CROSS_PARAM` and `SAME_PARAM`.
- `key{N}_ratios.csv` — pairwise ratios of the four nucleon
  quantities for each codon group under key `{N}`, given in
  both exact fractional form and decimal approximation.

Key-independent datasets (generated once):

- `amino_acids_proton_differences.csv`
- `amino_acids_neutron_differences.csv`
- `amino_acids_nucleon_differences.csv`

These three files enumerate, for every pair of the twenty
canonical amino acids, the absolute difference of proton, neutron
and total nucleon counts respectively, grouped by the value of
the difference.

Comparative dataset across NCBI codes:

- `deficit_models_analysis.csv` — applies the same nucleon
  bookkeeping to all 27 NCBI translation tables (numbered
  1–33, with gaps) to support the comparative analysis
  between the standard code and its natural variants.
- `keto_amino_balance_models.csv` — reports the keto/amino
  partition of the sense pool (third-position G/T vs A/C)
  in both neutron and proton counts, across all 27 NCBI
  translation tables (numbered 1–33, with gaps) and under
  both sense-pool models.
- `service_codon_balance_comparison.csv` — for every NCBI
  translation table and both service-excluded pool models,
  the minimal Keto/Amino compensation carried by the service
  codons, computed twice: with the balance condition alone and
  with the additional requirement that the global sum be
  divisible by 37. Reports the resulting assignments, the totals
  they produce, and the difference between the two procedures.

### Visualization

`visualization.html` is a single-page HTML application that provides an
interactive working environment for inspecting the genetic code
table and the arithmetic structure of its codon groups. It was
used during the exploratory phase of this study and is included
in the repository as a supplementary tool for readers who wish
to inspect the structure of the code interactively. It is not
required for reproducing any numerical result reported in the
preprint, and its CSV export functionality is independent of the
reproducibility pipeline (see "CSV export" below).

A hosted version of the visualizer is available at
[https://ruslankhafizov.github.io/genetic-code-arithmetic/](https://ruslankhafizov.github.io/genetic-code-arithmetic/)

The page requires no installation and performs all calculations
and CSV generation locally in the browser. Its interface libraries
(React, ReactDOM, Babel, Tailwind CSS, and tinycolor) are loaded
from public CDNs, so a network connection is required unless those
resources are already present in the browser cache. The application
does not upload selected codons or calculated results.

#### Main features

- **Translation table selector.** Switching between all 27 NCBI
  translation tables (numbered 1–33, with gaps) and two alternative
  parametrizations of the standard code that use different proton,
  neutron, and mass conventions for proline and glycine. The
  selector opens on the standard code by default.

- **Codon pool toggle.** A switch between the full 64-codon
  table ("ALL CODE") and the service-excluded pool. For the
  standard code, the button is labelled "POOL60": ATG, TAA,
  TAG, and TGA are excluded. For alternative tables, the
  "SERVICE-EXCLUDED POOL" button shows the number of remaining
  positions; ATG and the selected table's stop codons are excluded
  according to the pool model. Excluded positions are visually
  muted and removed from calculations, predefined groups, and
  CSV exports. These pool sums do not depend on service-codon
  key parameters.

  Tables with context-dependent stop codons offer two models:
  Model 1 excludes all declared stop codons; Model 2 restores
  contextual positions with their amino acid assignments and
  excludes only unconditional stop codons alongside ATG. This
  choice applies only to the pool; it changes neither the
  assignments under "ALL CODE" nor the STOP list in the key
  editor. Under "ALL CODE", all 64 positions are counted, with
  ATG and actual STOP contributions set by the active key.
  The excluded positions are listed below the toggle.

  The export filename identifies the pool mode: `pool60_*` for
  the standard pool, `sepool_*` for alternative-code pools; under
  "ALL CODE", the prefix follows the active key (for example,
  `key0_*` or `key1_*`). `Code_Section` identifies the group section.

- **Parametric keys.** Quick switching between the zero
  parametrization (Key 0), the symmetrization (Key 1), and
  additional reference keys defined in `key_parameters.csv`.
  Custom keys can be constructed by manually editing the
  nucleon contributions assigned to ATG and the actual STOPs
  of the active table. Stop codons can receive one shared
  assignment or individual values; the individual list depends
  on the selected table.

- **Amino acid editor.** A modal editor that allows the nucleon
  composition (protons, neutrons, side-chain mass, backbone
  mass) of any of the twenty canonical amino acids to be
  modified, for sensitivity analysis or hypothetical
  configurations.

- **Interactive codon matrix.** The 64 codons are displayed as
  an 8×8 matrix of 16 codon families, with per-codon nucleon
  values rendered live. Arbitrary subsets of codons can be
  selected by clicking, allowing custom codon groups to be
  constructed and analyzed without writing any code.

- **Live calculator and advanced analysis.** For any selected
  group of codons, the calculator computes the four nucleon
  quantities $P$, $N$, $T$ and $\Delta$, checks divisibility by
  37, 111 and 999, displays all pairwise ratios of these
  quantities in both exact-fraction and decimal form, and
  presents the values in the form $q \cdot 37 + r$ for direct
  visual inspection of divisibility. An expandable "Advanced
  Analysis" section breaks the $\Delta$ down per 8-codon block
  and reports the structural deltas between adjacent codon
  subsets.

- **Cross-set equality finder.** As the selection changes, the
  calculator scans all predefined codon groups in the
  demonstration panel (see below) and reports any numerical
  equalities between the nucleon quantities of the user-selected
  group and those of any predefined group, in real time. A
  scope toggle restricts the search either to the active
  demonstration tab or to the full set of predefined groups.

- **Demonstration panel.** A collection of preset codon groups
  organized into positional tabs (Pos 3, Pos 2, Pos 1), each
  representing the structural partition based on the chemical
  type of the nucleotide at the corresponding codon position.
  The Pos 3 tab corresponds to the codon-group partitioning
  used in this study, including the macro-groups defined by the
  third nucleotide and the Octet I / Octet II partition.
  Additional experimental groupings (Quartets, Combinatorial)
  are reached through a dropdown; some of these were introduced
  in earlier work on genetic code symmetries (Shcherbak and
  Makukov 2013, Panov and Filatov 2024) and others examined
  during the preparation of the present work, and the Quartets
  finer subdivisions are not discussed in the preprint. Each
  preset button displays the nucleon quantities of the
  corresponding group and updates as the parametric keys, amino
  acid values, or codon pool toggle are changed. Academic
  references shown on the buttons are clickable and link to the
  original publications via DOI.

- **Symmetry highlighting.** Three predefined nucleotide
  permutations can be applied to highlight related codons on
  the matrix: the Rumer transformation $R = (T \leftrightarrow
  G,\, C \leftrightarrow A)$, the transition $(T \leftrightarrow
  C,\, A \leftrightarrow G)$, and the transversion
  $(T \leftrightarrow A,\, G \leftrightarrow C)$. The Rumer
  transformation discussed in the preprint can be visually
  verified through this feature. Independently of the selected preset, hovering over any codon
  block in the matrix outlines that block together with its image
  under the currently active transformation, allowing the action
  of each permutation to be inspected interactively.

- **Alternative representations of the code table.** The order
  of nucleotides on the matrix axes can be reordered, generating
  alternative visual representations of the genetic code table.
  All 24 orderings are accessible through this feature.

- **Numeral system toggle.** Numerical values can be displayed
  in standard decimal notation or in base 37. In base 37, a
  number is divisible by 37 if and only if its representation
  ends in zero, allowing divisibility by 37 to be checked
  visually for any displayed value without arithmetic. Higher
  divisibilities (such as multiples of 111 or 999) are not
  distinguished by additional trailing zeros and remain
  indicated by the divisibility badges shown next to each value.

- **Decomposition into the Shcherbak–Makukov form.** For
  nucleon sums that are multiples of 37, the calculator
  attempts to express the value in the form $999n + 111m$,
  the canonical decomposition used in the original work of
  Shcherbak and Makukov, and reports the result when such a
  decomposition exists.

#### CSV export

For the active demonstration tab the page offers four independent
CSV exports: **Nucleons** (the quantities P, N, T and Δ for each
group), **Divisibility** (the same quantities with their
divisibility-by-37 analysis), **Ratios** (the pairwise ratios of
the four quantities), and **Equalities** (the cross-set numerical
coincidences listed by the equality finder). A separate **export
scope** toggle controls the column set: "STRICT" exports only the
invariant quantities (T, P, N, Δ), while "FULL" additionally
exports the side-chain and backbone mass components.

In the canonical configuration — the standard code, the Pos 3
tab, STRICT scope, decimal notation, no manual codon selection,
unmodified amino-acid values, and TAB equality scope — the page
uses the same short filenames as the reproducibility pipeline:
`pool60_*`, `key0_*`, or `key1_*`. The four canonical POOL60
exports have been verified to be bit-for-bit identical to the
corresponding files generated by `reproduce.py`.

Alternative-code pool exports use the `sepool` prefix followed by
the code name. Context-dependent tables additionally include
`model1` or `model2`. For example:
`sepool_vertebrate-mitochondrial_nucleon-data.csv`.
Further qualifiers reflect the other export settings.

Any noncanonical state receives a qualified, self-describing
filename indicating the relevant code, tab, equality scope,
column scope, numeral system, manual selection, or amino-acid
modification. The exported content always reflects the active
tab, codon-pool toggle, export scope, and any manual edits or
selection; under ALL CODE it also reflects the active key.
`Code_Section` records the group section (for example,
"All code", "Octet I", or "Octet II") or the experimental tab;
the filename records the pool mode. An Equalities export with the
ALL search scope additionally includes `Source_Tab` and
`Target_Tab` so that group IDs reused across tabs remain
unambiguous.

For archival reproduction of the complete set of eighteen
computed datasets, `reproduce.py` remains the normative pipeline:
it reads the five published input datasets, validates their
structure, and writes all outputs deterministically in one run.
The visualization export additionally supports exploratory and
custom configurations that are intentionally outside that core
pipeline.

### Supplementary controls

The script `controls.py` writes four files: results of three specificity
controls — codon position, choice of modulus, and molecular representation —
and a cross-table comparison of Keto/Amino differences. The latter describes
a post hoc observation. The script uses the Python standard library and
exact arithmetic without randomization. It reads the same five input files
as `reproduce.py` but is separate from its 18-output pipeline.
Details and run commands are given below.

- `controls.py` — the three controls and cross-table comparison.
- `position_axis_analysis.csv` — the three chemical axes at each codon
  position for the service-excluded pool, Key 0, and Key 1. The machine value
  `sense` specifically excludes ATG and the three stop codons. In this pool,
  eleven group quantities are divisible by 37 at the third position,
  two dependent Keto/Amino neutron sums at the first, and none at the second.
- `prime_divisibility_scan.csv` — divisibility counts for primes up to 97,
  over all quantity instances, distinct nonzero values, and odd cores.
  The ratio of the divisible distinct-value share to the 1/p benchmark is
  descriptive; it is not a p-value. By this metric, 37 ranks first in all
  three sets, including before the Key 1 assignments.
- `position_asymmetry_ncbi.csv` — Keto-minus-Amino differences in T, P, N,
  and Δ at three positions for 27 NCBI tables under two pool models.
  The N/T/N divisibility pattern recurs in Tables 1/11/28 under Model 1
  and 1/11 under Model 2; their analyzed pools match the standard pool.
  This is a post hoc comparison, not a probability estimate.
- `representation_sensitivity.csv` — 13 quantities under the neutral free
  amino acid, peptide residue, and zwitterion representations. Uniform
  shifts preserve molecular differences and differences between equal-size
  groups; absolute values change in the peptide representation. The
  zwitterion retains the original nucleon counts because its atoms do not
  change.

A further script, `mc_significance.py`, assesses the *statistical significance*
of the structure under a random-code null (a random reassignment of the twenty
amino acids to the synonymous blocks). Unlike `controls.py` it is randomized,
though seeded for reproducibility. See its dedicated section below.

- `mc_significance.py` — the Monte Carlo significance test.
- `mc_significance.csv` — its summary table: six statistical summaries,
  their observed values, null means, tail counts, p estimates, and Monte
  Carlo uncertainty intervals.
- `verify_mc.py` — an independent re-implementation of the Monte Carlo (a
  different construction of the codon groups, a direct derivation of Key 1,
  and a different fixed random seed, sharing no code with
  `mc_significance.py`) that reproduces the results within the expected
  Monte Carlo error, as a guard against coding error.


- `mc_sensitivity.py` and `mc_sensitivity.csv` — additional checks of
  positive distances and the model with methionine fixed.
- `verify_mc_sensitivity.py` — an independent check of this supplement.

## File format conventions

All CSV files in this repository follow the same conventions:

- Encoding: UTF-8.
- Field delimiter: comma (`,`).
- Quoting: all string fields are quoted with double quotes,
  all numeric fields are unquoted (equivalent to Python's
  `csv.QUOTE_NONNUMERIC`).
- List separator within a quoted field: semicolon (`;`).
- Line ending: LF (`\n`).
- Trailing newline: every file ends with a single LF character.
- Row ordering: deterministic within each file; see the
  `reproduce.py` section for the sorting rule applied to each
  computed dataset.

Codons are represented in DNA notation using the alphabet
`{A, T, G, C}`. Amino acids are denoted by full names, standard
three-letter codes, or single-letter IUPAC codes as appropriate.
Stop codons are denoted by an asterisk (`*`) in single-letter
notation.

The 64 codons of the genetic code are partitioned into two
structural halves of 32 codons each:

- **Octet I** — the 32 codons belonging to the eight fully
  four-fold degenerate codon families (GCN, CGN, GGN, CCN, ACN,
  GTN, CTN, TCN), in which the third nucleotide does not affect
  the encoded amino acid.
- **Octet II** — the remaining 32 codons, belonging to codon
  families with mixed or lower degeneracy. All four service
  codons of the standard code (the three stop signals TAA, TAG,
  TGA and the start signal ATG) belong to Octet II.

Unless otherwise noted, datasets describe the standard genetic
code (NCBI translation table 1). The files
`ncbi_genetic_code_registry.csv`, `deficit_models_analysis.csv`,
`keto_amino_balance_models.csv` and
`service_codon_balance_comparison.csv` cover all genetic code
variants recognized by NCBI (27 translation tables, numbered
1–33, with gaps).

## The reproducibility script `reproduce.py`

All eighteen computed datasets in this repository are generated from
the five input datasets by a single Python script, `reproduce.py`.
The script is the authoritative definition of how the computed
datasets are derived; the computed datasets themselves are provided
for convenience but can be regenerated at any time.

### Requirements

- Python 3.8 or later.
- Standard library only. No external packages are required or
  used. In particular, the script does not depend on `numpy`,
  `pandas`, or any other third-party library, and does not require
  a virtual environment.

### Usage

Run the script from the repository directory:

    python3 reproduce.py

The script reads the five input CSV files from the current
directory and writes the eighteen computed CSV files to the same
directory, overwriting any existing files of the same name.
No command-line arguments, configuration files, environment
variables, or interactive prompts are used. On successful
completion the script prints a single summary line and exits with
status 0.

### Determinism

The script is fully deterministic. Running it twice on the same
input files produces eighteen output files that are identical
byte-for-byte, and identical across operating systems and Python
versions within the supported range. This determinism is achieved
by three properties:

1. All arithmetic is performed in exact integer arithmetic, with
   the single exception of the decimal approximations in the
   `*_ratios.csv` files, which are computed from exact rational
   values and rounded to a fixed number of decimal places.
2. Every output row is produced by an explicit deterministic
   sorting rule (described below), without any reliance on
   dictionary iteration order, set ordering, or filesystem
   ordering.
3. All output files are written with a fixed CSV dialect
   (`csv.QUOTE_NONNUMERIC`, LF line endings, trailing newline),
   independent of the host platform.

### Sorting rules

Each computed dataset uses a single, explicit sorting rule applied
uniformly to all rows of the file, without special cases:

- `pool60_nucleon-data.csv`, `pool60_divisibility-37.csv`,
  `pool60_ratios.csv`, and the corresponding `key{N}_*` files — rows
  are sorted by `Group_ID` in ascending
  order (1 through 33), matching the group numbering defined in
  `codon_groups.csv`.
- `pool60_equalities.csv` and `key{N}_equalities.csv` — rows are
  sorted primarily by
  `Nucleon_Value` in ascending order, then by `Match_Type` in the
  order `DIFF_PARAM`, `CROSS_PARAM`, `SAME_PARAM`, then by
  `Source_ID` in ascending order, then by `Target_ID` in ascending
  order. This places smaller-magnitude equalities first and, within
  each equality value, reports the structurally stronger equality
  types before the weaker ones.
- `amino_acids_proton_differences.csv`,
  `amino_acids_neutron_differences.csv`,
  `amino_acids_nucleon_differences.csv` — rows are sorted by the
  value of the difference in ascending order. Within each row, the
  list of amino acid pairs (stored in the `Amino_Acid_Pairs` column
  as a semicolon-separated string) is itself sorted alphabetically.
- `deficit_models_analysis.csv`,
  `keto_amino_balance_models.csv` — rows are sorted by NCBI
  translation table identifier in ascending order (1 through 33).
- `service_codon_balance_comparison.csv` — rows are sorted by NCBI
  translation table identifier in ascending order, then by `Model`
  (1 before 2). Every table contributes exactly two rows.

## The supplementary control script `controls.py`

The script reproduces the numerical results of the three controls and
cross-table comparison in Section 4.2. Its four output files supplement the
18 datasets from `reproduce.py`; it is not required to generate those 18.

### Requirements

Python 3, standard library only. No network or third-party packages are needed.

### Usage

```text
python3 controls.py
```

The script reads `amino_acids_nucleons.csv`, `genetic_code_codons.csv`,
`codon_groups.csv`, `key_parameters.csv`, and `ncbi_genetic_code_registry.csv`
from its own directory and writes the four output CSVs there.

### Determinism

There is no randomization; counts and residues are integers, and output is
byte-for-byte reproducible. `Expected_Distinct` stores the benchmark
`Total_Distinct / Prime` as an exact reduced fraction. This is a uniform-residue
benchmark, not an expectation under a random-genetic-code null model.

### Three controls and a cross-table comparison

1. **Codon position** (`position_axis_analysis.csv`). The chemical axes are
   applied at each position under three counting modes. The comparison in
   Section 4.2 concerns the service-excluded pool (`Pool=sense`). At the third
   position, all four quantities of Amino and Weak are divisible, as are N
   of Keto and Strong and Δ of Pyrimidine. Keto and Strong P and T are one
   below a multiple of 37. At the first position, only Keto and Amino N are
   divisible; given divisibility of the full N sum, either implies the other.
   At the second position, none of the four quantities of the six groups is
   divisible. Excluding service codons can give unequal half sizes:
   Keto/Amino contain 29/31 codons at the first position and 30/30 at the third.
   Key 0 and Key 1 values are also retained in the CSV.

2. **Choice of modulus** (`prime_divisibility_scan.csv`). Primes up to 97 are
   scanned for three T/P/N/Δ sets: the 17 groups with no service codon
   (`param_independent`), all 33 groups under Key 0, and all 33 under Key 1.
   The first set consists of complete groups with no service codon, not all
   33 groups after service codons have been removed. If p divides k of m
   distinct nonzero values, the ratio of k/m to the 1/p benchmark is pk/m.
   For 37, the divisible shares are 5/28, 13/70, and 10/47, with ratios of
   about 6.61, 6.87, and 7.87 — the highest in all three sets. For 2 and 5,
   the ratios are below three. The statistic is bounded by p and changes in
   steps of p/m; both depend on the modulus. The scan specifies no code null
   model and yields no p-value. Prime powers impose additional divisibility
   conditions and are outside the scan; no value in these sets is divisible
   by 37². Removing duplicate values does not remove algebraic dependencies.
   Odd cores collapse copies v, 2v, 4v but do not establish independence.
   Under Key 0, multiples of 37 yield ten cores; multiples of 73 and 61
   yield one each (73 and 549, respectively).

3. **Molecular representation** (`representation_sensitivity.csv`).
   Thirteen quantities are checked under uniform shifts (ΔP, ΔN): (0,0)
   for the neutral free amino acid, (−10,−8) for the peptide residue, and
   (0,0) for the zwitterion. The peptide model subtracts one H2O from each
   molecular formula; the zwitterion retains the original atoms. Shifts
   cancel in molecular differences and differences between equal-size groups,
   preserving the tryptophan–isoleucine and third-position Keto/Amino and
   Strong/Weak differences. This does not imply robustness to arbitrary
   changes of molecular representation. Divisibility of the full pool N
   survives if and only if 60·ΔN ≡ 0 (mod 37), hence ΔN ≡ 0 (mod 37).
   The peptide model gives N=3109 and P=3580, and Keto/Amino neutron sums
   of 1573/1536: the difference 37 survives, while divisibility of the sums
   is lost. The deficit is computed within one representation:
   3124−3109=15, instead of the original 111. The zwitterion reproduces
   all original values.

4. **Cross-table Keto/Amino comparison** (`position_asymmetry_ncbi.csv`).
   This is an additional post hoc observation. Keto-minus-Amino T/P/N/Δ
   differences are computed at three positions for 27 NCBI tables.
   Model 1 excludes ATG and everything listed in `Stop_Codons`; Model 2
   returns context-dependent stop codons with their amino-acid assignments.
   In the standard code, the divisible differences by position are N/T/N:
   −333/185/37. At the third position, the difference reduces to the
   tryptophan–isoleucine pair. The N/T/N pattern recurs only in 1/11/28
   under Model 1 and 1/11 under Model 2; their analyzed pools match the
   standard pool. In the other tables it persists at no more than one
   position. The CSV contains all four differences, not only the selected
   sequence. The sequence was selected after inspecting the data; counting
   matches among evolutionarily related tables does not estimate a probability.

### Consistency check

The script checks third-position groups against `codon_groups.csv`; the first
two positions are built directly from the 64 codons. It also checks the
baseline representation values and the tables having at least one divisible
difference at each of the three positions. Machine names `sense`,

## The Monte Carlo significance test `mc_significance.py`

`mc_significance.py` evaluates six specified arithmetic summaries under an
explicit null, complementing the deterministic specificity controls above.
Unlike the deterministic `reproduce.py` and `controls.py`, it is randomized
(though seeded).

### Requirements

Python 3, standard library only. No third-party packages are required.

### Usage

```
python3 mc_significance.py
```

The script reads `amino_acids_nucleons.csv`, `genetic_code_codons.csv`
and `codon_groups.csv` and writes a summary
table `mc_significance.csv`.

### Null model

The model is a "random code" of the kind used in studies of genetic-code
optimality. The architecture of the standard code is held fixed: the 64 codons,
the synonymous blocks with their sizes, the three stop codons, the Rumer
Octet I/II partition, and the third-position chemical axes. A trial uniformly
permutes the twenty real paired proton and neutron profiles over the twenty
blocks; the P and N components of an amino acid always move together. The
modulus 37 is taken from prior literature. The statistical
summaries were formally defined before the final run, but the analysis was not
preregistered before inspection of the observed structure and is therefore
interpreted as exploratory.

### Reproducibility

The script is randomized but seeded (default seed 0, 1,000,000 trials), so the
reported figures are reproducible run to run.
For each statistic it reports the number `b` of random codes at least as
extreme as the standard code, the estimate
`p_MC = (b + 1) / (M + 1)`, and a 95% Monte Carlo uncertainty interval.

### Six statistical summaries

1. **S1 — joint divisibility of two anchors.**
   `N(service-excluded pool) = 3589 = 97·37` and
   `T(Octet I) = 3700 = 100·37` are both divisible by 37 in a fraction
   0.000800 of random codes (95% interval 0.000746–0.000856).
   This is the directly estimated joint probability; independence of the
   anchors is not assumed.
2. **S2 — divisibility count for the headline service-excluded partition.**
   Across T/P/N/Δ for nine groups, the standard code has 13 divisible
   quantities out of 36, against a null mean of 1.0299. A value of 13 or
   greater occurs in 39 of 1,000,000 trials:
   `p_MC = 4.0×10⁻⁵`, interval 2.9×10⁻⁵–5.3×10⁻⁵.
3. **S3 — the same count for 17 groups containing no service codons.**
   The standard code has 14 divisible quantities out of 68 against a null
   mean of 2.1311, `p_MC = 0.025135`
   (interval 0.024829–0.025443). Eleven divisibilities are structural copies
   of `T(Octet I) = 100·37`, and three form the pyrimidine Δ-cascade, so S3
   is treated as a secondary summary.
4. **S4sense — mean proximity of the service-excluded pool to the 37-lattice.**
   For 33 groups, the distances of T/P/N/Δ to the nearest multiple of 37 are
   averaged, including zero distances; 132 quantities are included. The
   observed mean is 4.8182 against a null mean of 9.1495,
   `p_MC = 0.000274` (interval 0.000242–0.000307).
   No values are assigned to service codons.
5. **S4a — the same distance under Key 0.**
   In each random code the ATG contribution is the amino acid actually
   assigned to the ATG block, while stop codons contribute zero. The observed
   mean is 5.5606 against a null mean of 9.0157,
   `p_MC = 0.002807` (interval 0.002704–0.002912).
6. **S4b — a symmetric test of the Key 1 procedure.**
   Each random code receives its own minimal non-negative Key 1, re-derived by
   the same balance and divisibility conditions. The observed mean is 4.6364
   against a null mean of 7.7397,
   `p_MC = 0.021106` (interval 0.020825–0.021389).

The central statistical results are S2 and S4sense, both free of service-codon
assignments. They describe the same overall concentration in different ways,
are dependent, and are not combined by multiplying their p-values. The weaker
S3 shows that restricting the analysis to nested groups without service codons
leaves mainly two structural cascades. S4a and S4b are secondary tests of the
extension to the complete table.

These nominal p-values describe the specified summaries under this null, which fixes
the degeneracy architecture and the real amino-acid nucleon counts. This is a
different question from specificity among the 27 natural codes and does not
identify a biological mechanism.

## Additional checks in `mc_sensitivity.py`

This separate exploratory analysis leaves the six main summaries in
`mc_significance.py` unchanged. It compares S2, S4sense and S4pos in two models:

- `relabel20`: the same uniform permutation of 20 paired P/N profiles as
  in the main analysis;
- `fixed_atg_met19`: methionine remains at ATG and the other 19 profiles
  are uniformly permuted among the remaining blocks. The amino-acid
  composition of the service-excluded pool is thereby held fixed.

ATG, TAA, TAG and TGA are excluded from every group in both models.
In the main model this removes whichever amino acid was assigned to ATG;
the conditional model examines the role of that choice. Block sizes are
fixed, but the number of codons assigned to a particular permuted amino
acid can change. Neither model describes an evolutionary process.

S2 and S4sense retain their original definitions and weights. Repeated
groups retain their full multiplicities. **S4pos** is the mean of only
the positive distances within the same set of 132 distances; their number
is recalculated for every code. The standard code has 104 positive distances
with a sum of 636. If all distances are zero, the statistic is defined as 0;
such trials are included in the tail and counted separately. This is a
special-case convention, not the mean of an empty set. No such cases occurred
in any of the saved main or independent supplementary runs.

### amino_acids_nucleons.csv

This dataset reports the integer nucleon composition of the 20 canonical amino acids.

The values are not measured molecular masses.
They are derived integer quantities computed from atomic composition using standard physical principles.

#### Molecular representation

Each amino acid is represented as a neutral free amino acid molecule
(not as a residue in a peptide chain).

The molecular formula for each amino acid follows standard biochemical references.

#### Proton count

The number of protons is computed as the sum of atomic numbers of all atoms
in the molecular formula:

P = Σ Zᵢ

where Zᵢ is the atomic number of element i.

Atomic numbers used:
- Hydrogen (H): Z = 1
- Carbon (C): Z = 6
- Nitrogen (N): Z = 7
- Oxygen (O): Z = 8
- Sulfur (S): Z = 16

#### Neutron count

The number of neutrons is computed assuming the most abundant stable isotope
of each element.

For each atom, the neutron count is:

Nᵢ = Aᵢ − Zᵢ

where:
- Aᵢ is the mass number of the most abundant stable isotope,
- Zᵢ is the atomic number of element i.

The total neutron count is obtained by summation over all atoms:

N = Σ (Aᵢ − Zᵢ)

Isotopes used:
- H-1
- C-12
- N-14
- O-16
- S-32

#### Total nucleon count

The total nucleon count is defined as:

T = P + N

This quantity is an integer by construction and reflects the total number of
nucleons in the molecular composition.

#### Proton–neutron imbalance

The column `Delta_P_N` is defined as:

Δ(P−N) = P − N

This value characterizes proton–neutron asymmetry in the amino acid molecule.

Under the isotope assumptions used here, proton–neutron imbalance arises exclusively from hydrogen atoms, which contribute one proton and zero neutrons:

Delta_P_N = number_of_hydrogen_atoms

#### Columns

- `Amino_Acid` — amino acid name
- `Total_Nucleons` — total nucleon count (P + N)
- `Protons` — total number of protons
- `Neutrons` — total number of neutrons
- `Delta_P_N` — proton–neutron difference

### amino_acids_neutron_differences.csv

This dataset reports the distribution of absolute differences in neutron count
between all unordered pairs of the 20 canonical amino acids.

The neutron counts used for each amino acid are taken directly from
`amino_acids_nucleons.csv` and are computed under the same isotope assumptions.

#### Pair construction

The dataset includes all possible unordered pairwise comparisons of distinct
amino acids.

Self-pairs (A–A) are excluded.
Pair order is irrelevant: a pair A–B is considered identical to B–A and is
counted once.

For a set of 20 amino acids, the total number of unique unordered pairs is:

C(20, 2) = 20 × 19 / 2 = 190

All pair counts reported in this table sum to 190.

#### Neutron difference

For each unordered pair of amino acids (i, j), the neutron difference is defined as:

ΔN = |Nᵢ − Nⱼ|

where Nᵢ and Nⱼ are the total neutron counts of the two amino acids.

Only non-negative integer differences are possible by construction.

#### Parity constraint

The parity of the neutron count of an amino acid is determined by the parity
of its hydrogen and nitrogen atom counts, which always coincide
(see `amino_acids_proton_differences.csv`). This yields a natural partition
of the 20 amino acids into two groups:

- Group 1 (15 amino acids): odd H count, odd N count — neutron count is odd,
  total nucleon count is odd.
  Members: Gly, Ala, Ser, Pro, Val, Thr, Cys, Ile, Leu, Asp, Glu, Met,
  His, Phe, Tyr.

- Group 2 (5 amino acids): even H count, even N count — neutron count is even,
  total nucleon count is even.
  Members: Asn, Gln, Lys, Arg, Trp.

A consequence of this partition is that neutron differences between two amino
acids from the same group are always even, while neutron differences between
amino acids from different groups are always odd.

#### Coverage

The table includes all integer values of ΔN from 0 to the observed maximum of 61.
Integer values for which no amino acid pair exists are explicitly listed with
Number_of_Pairs = 0 and Amino_Acid_Pairs = "No pairs found".

Of the 62 possible integer values in this range, 47 correspond to at least one
amino acid pair, and 15 are not realized by any pair. The unrealized values are
not uniformly distributed: their pattern is consistent with the parity partition
described above, as cross-group differences (always odd) and within-group
differences (always even) together constrain which values are achievable.

#### Degenerate cases

Pairs with ΔN = 0 correspond to amino acids that have exactly the same total
neutron count despite differing molecular composition.

Such degeneracies arise naturally within the canonical amino acid set and are
explicitly included in the dataset as a separate table entry.

#### Columns

- `Neutron_Difference` — absolute difference in total neutron count (ΔN)
- `Number_Of_Pairs` — number of unordered amino acid pairs exhibiting this difference
- `Amino_Acid_Pairs` — semicolon-separated list of amino acid name pairs
  corresponding to the given neutron difference, or "No pairs found" if no pair exists

Each amino acid pair appears exactly once in the entire table.

### codon_groups.csv

This dataset contains 33 codon groups used in the analysis of genetic code symmetries.

Each group represents a subset of the 64 codons of the standard genetic code,
selected according to specific structural criteria.

#### Group name notation

Group names use set notation to specify the nucleotides present in the third
(wobble) position of codons within the group.

Format: `GroupType: {nucleotides}`

Examples:
- `ALL: {C, G, A, T}` — codons with any nucleotide in third position (all 64 codons)
- `Keto: {G, T}` — codons ending in G or T (keto bases)
- `{C}` — codons ending only in C

The set notation {·} indicates that order is not significant: 
{G, T} is equivalent to {T, G}.

Third position groups:
- Keto {G, T} vs Amino {A, C} — chemical properties (keto vs amino groups)
- Strong {C, G} vs Weak {A, T} — hydrogen bonding strength (3 vs 2 bonds)
- Purine {A, G} vs Pyrimidine {C, T} — base structure (double vs single ring)

#### Twin groups

Certain codon groups share identical amino acid composition but are represented
by different codon sets. Such groups are termed "twin groups" and are cross-referenced
via the `Twin_Group_ID` field.

Twin groups arise from pyrimidine synonymy: in every codon
family of the standard genetic code, the codons NNC and NNT
encode the same amino acid. As a result, codon groups that
differ only in whether their third-position nucleotide set
contains C or T encode the same multiset of amino acids.
For example, Keto {G,T} and Strong {C,G} are twins: the
substitution T → C transforms one set into the other while
preserving the encoded amino acid composition.

Twin group pairs in this dataset:
- Groups 2 ↔ 3: Keto {G,T} ↔ Strong {C,G}
- Groups 4 ↔ 5: Amino {A,C} ↔ Weak {A,T}
- Groups 13 ↔ 14: {G,T} ↔ {C,G} (Octet I)
- Groups 15 ↔ 16: {A,C} ↔ {A,T} (Octet I)
- Groups 24 ↔ 25: {G,T} ↔ {C,G} (Octet II)
- Groups 26 ↔ 27: {A,C} ↔ {A,T} (Octet II)

#### Single-nucleotide groups {C} and {T}

The single-nucleotide groups {C} (Group_ID 8, 19, 30) and
{T} (Group_ID 10, 21, 32) encode identical amino acid
multisets and have identical nucleon quantities under any
parametric key. This identity is a direct consequence of
pyrimidine synonymy: a codon ending in C and the same codon
ending in T encode the same amino acid by definition.

These pairs are not recorded in `Twin_Group_ID`, which is
reserved for pairs whose identical amino acid composition
arises from pyrimidine synonymy across a two-nucleotide
chemical axis (Keto/Strong or Amino/Weak). The Purine/Pyrimidine
axis is excluded from this column because Purine contains all
four service codons while Pyrimidine contains none, so the
two groups have substantially different amino acid composition
outside Octet I. The {C}/{T} pair is also not such a pair: it
arises from a single one-nucleotide selection rather than from
a chemical opposition between two-nucleotide subsets.
The identity of {C} and {T} is documented here for
completeness.

#### Octet I degeneracy property

Octet I (groups 12–22) consists entirely of 4-fold degenerate codon families,
where the third (wobble) position does not affect amino acid identity. 
As a consequence, all groups within Octet I that share the same pattern of 
third-position nucleotides encode identical amino acid multisets.

Specifically:

Groups 13–18 (size 16 each): All six groups encode the same multiset 
of amino acids. These groups differ only in which 
two of the four nucleotides appear in the third position.

Groups 19–22 (size 8 each): All four groups encode the same multiset 
of amino acids. These groups each contain codons 
ending in a single nucleotide.

This property is distinct from "twin groups" (§ Twin groups),
which arise from pyrimidine synonymy and the chemical structure
of the partitioning, not from degeneracy of the codon families
themselves.

In Octet II (groups 23–33), this property does not hold, as Octet II contains 
codon families with varying degeneracy.

Note: Octet groups follow the same partitioning patterns as 
the All code section, restricted to codons within their respective octets.

#### Columns

- `Group_Name` — descriptive name of the group
- `Group_ID` — unique integer identifier for the codon group
- `Twin_Group_ID` — identifier of the twin group sharing identical amino acid composition, or empty string if no twin exists
- `Code_Section` — partition of the genetic code to which the group belongs:
"All code" (Group_ID 1–11), "Octet I" (Group_ID 12–22), or "Octet II" (Group_ID 23–33).
- `Group_Size` — number of codons in the group
- `Codon_List` — semicolon-separated list of DNA codons in the group
- `Amino_Acid_List` — amino acid sequence encoded by the codon group, using single-letter IUPAC notation; asterisks (*) denote stop codons.

### key_parameters.csv

This dataset defines ten parametric keys (key0–key9), each of
which specifies nucleon values assigned to the four service
codons of the standard genetic code (the start codon ATG and the
three stop codons TAA, TAG, TGA). Two of these keys, key0 and
key1, are analyzed in the accompanying preprint as the two
principal parametrizations; key0 is the zero parametrization, in
which stop codons contribute zero and ATG is treated as ordinary
methionine, and key1 is the symmetrization, in which stop codons
and ATG are assigned values derived analytically from symmetry
constraints. The remaining keys key2–key9 are included for
reference and are not discussed in the preprint.

#### Purpose

Each parameter set represents a different configuration of nucleon counts assigned to:
- The start codon (ATG, encoding Methionine)
- The stop codons (TAA, TAG, TGA)

By varying these parameters, the analysis tests whether observed nucleon patterns persist across different boundary conditions of the genetic code.

#### Key sets

key0 — **zero parametrization**. Start codon ATG is assigned the
standard methionine nucleon values; the three stop codons are
assigned zero nucleon values in all parameters. This is the
reference configuration used whenever service codons should not
contribute to nucleon sums.

key1 — **symmetrization**. Start codon ATG is assigned
`(P, N) = (1, 0)`; each of the three stop codons is assigned
`(P, N) = (37, 37)`. These values are derived analytically in
the preprint as the minimal nonnegative integer solution of a
system of symmetry constraints on nucleon quantities across
codon macro-groups.

key2–key9 — additional parametric keys not analyzed in the main
text of the preprint. Included in the dataset for reference and
for readers who wish to explore alternative configurations.

#### Standard nucleon values

Methionine (product of start codon ATG):
- Side-chain: 75 nucleons
- Backbone: 74 nucleons
- Protons: 80
- Neutrons: 69

#### Column structure

Modification columns (Mod_*):

Integer offsets applied to standard values.

For start codon (ATG):

Final_Value = Standard_Methionine + Mod_Value

For stop codons (TAA, TAG, TGA):

Final_Value = 0 + Mod_Value = Mod_Value

(Note: In key0, stop codons have Mod_Value = 0, hence Final_Value = 0)

Final columns (Final_*):

Resultant nucleon counts used in symmetry calculations.

#### Data structure

Each parameter set (key0–key9) contains 4 rows:
- 1 row for start codon (ATG)
- 3 rows for stop codons (TAA, TAG, TGA)

Total: 40 data rows (10 keys × 4 codons)

#### Columns

- `Key_ID` — unique identifier (key0–key9)
- `Codon` — DNA codon (ATG, TAA, TAG, or TGA)
- `Mod_Side_Chain` — offset for side-chain nucleons
- `Mod_Backbone` — offset for backbone nucleons
- `Mod_Protons` — offset for proton count
- `Mod_Neutrons` — offset for neutron count
- `Final_Side_Chain` — resultant side-chain nucleon count
- `Final_Backbone` — resultant backbone nucleon count
- `Final_Protons` — resultant proton count
- `Final_Neutrons` — resultant neutron count

### ncbi_genetic_code_registry.csv

This dataset lists all genetic code variants currently recognized by the
National Center for Biotechnology Information (NCBI), including the
standard code and all known alternative codes.

The data were retrieved from the NCBI Taxonomy genetic codes page:
https://www.ncbi.nlm.nih.gov/Taxonomy/Utils/wprintgc.cgi

Each genetic code is identified by its translation table number
(transl_table), as used in GenBank feature annotations and
bioinformatics tools.

#### Translation table numbering

Translation table numbers are assigned by NCBI and are not contiguous.
Numbers 7, 8, 17, 18, 19, and 20 are absent from the current registry:
these entries were either never assigned or were subsequently withdrawn
and merged with other codes.

#### Amino acid string format

The column `Amino_Acids` contains the ncbieaa string as defined by NCBI.
This is a 64-character string in which each character represents the
translation product of one codon. The order of codons follows the
standard NCBI enumeration: TTT, TTC, TTA, TTG, TCT, TCC, ... (all 64
codons in T→C→A→G order at each position). An asterisk (*) denotes a
stop codon, except in context-dependent codes (transl_table 27, 28, 31)
where amino acid letters are used instead (see below).

#### The Bacterial, Archaeal and Plant Plastid Code (transl_table=11)

This code is identical to the Standard Code (transl_table=1) in its
amino acid assignments and stop codons. It is listed as a separate entry
because bacteria, archaea, and plant plastids use an extended set of
start codons: in addition to ATG, the codons GTG, TTG, ATT, and CTG can
initiate translation in these organisms.

#### Context-dependent stop codons (transl_table=27, 28, 31)

Three codes in this dataset — Karyorelict Nuclear (27), Condylostoma
Nuclear (28), and Blastocrithidia Nuclear (31) — contain no asterisk (*)
in their `Amino_Acids` string and have `Stop_Context_Dependent` set to
True. This is not an error.

These codes use context-dependent decoding: certain codons are read as
an amino acid in the middle of a protein-coding sequence, and as a stop
signal at the end of a gene. NCBI records an amino acid letter (Q, W,
or E) rather than * in the ncbieaa string to prevent translation tools
from incorrectly truncating proteins at these positions.

The actual stop codons for these organisms are listed in the
`Stop_Codons` column of this dataset. On the NCBI source page,
positions corresponding to these codons are marked with an asterisk (*)
in the Starts line.

- `Transl_Table` — NCBI translation table number
- `Code_Name` — full name of the genetic code as given by NCBI
- `Amino_Acids` — 64-character ncbieaa string representing the
  translation product of each codon in standard NCBI order; asterisk
  (*) denotes a stop codon, except in context-dependent codes
  (transl_table 27, 28, 31) where amino acid letters are used instead
  (see Context-dependent stop codons section above)
- `Stop_Codons` — comma-separated list of codons that function as
  stop signals in this code
- `Stop_Context_Dependent` — boolean flag indicating whether the code
  uses context-dependent stop codon decoding; True for transl_table
  27, 28, and 31, False for all other codes
  
### deficit_models_analysis.csv

This dataset provides a comparative arithmetic analysis of
the sense-pool of the standard code across all genetic
code variants recognized by NCBI (27 translation tables,
numbered 1–33, with gaps). Two structurally distinct tests
are tabulated:

(1) the neutron deficit of the sense pool relative to
three reference anchors derived from Octet I (the constant
3700, the structural T(Octet I), and the functional
T(Octet I)). For the standard code all three deficits
equal 111 = 3·37.

(2) the residue of the sense-pool proton count modulo 37,
without reference to any Octet I-based anchor. For the
standard code this residue is -1 ≡ 36 (mod 37), the
parity-induced unit shift consistent with the structural
forbiddenness of |δP| = 37 for any pair of canonical
amino acids.

The two tests reflect different aspects of how the
standard code's sense pool aligns with the 37-lattice: the
neutron test through dimensional matching against the
Octet I scale, the proton test through residue analysis
alone.

This dataset is generated by `reproduce.py` from
`amino_acids_nucleons.csv` and `ncbi_genetic_code_registry.csv`
together with the other seventeen computed datasets in this
repository. See the "The reproducibility script `reproduce.py`"
section above for details on how to regenerate it.

#### Sense codons excluding the ATG initiator

The columns `N_Pure` and `Pure_Codons_Count` are computed over the set
of sense codons excluding the ATG initiator. ATG encodes Methionine and
is a fully functional sense codon at any internal position; it is
excluded here solely in its role as the universal initiation codon. All other sense codons, including alternative start codons such as
GTG and TTG, retain their amino acid meaning during elongation and are
included.

Stop codons are taken from the `Stop_Codons` column of
`ncbi_genetic_code_registry.csv` rather than inferred from the
`Amino_Acids` string.

The excluded codons are therefore:
- all codons listed in the `Stop_Codons` column for each translation table
- one ATG initiator codon

The codon count is thus defined as:

Pure_Codons_Count = 64 − Stop_Count − 1

where Stop_Count is the number of codons listed in the `Stop_Codons`
column of `ncbi_genetic_code_registry.csv` for the given translation
table.

In the notation of the preprint, this sense pool is written
`N(All sense)` and `P(All sense)`; the dataset columns with the
`_Pure` suffix (`N_Pure`, `P_Pure`, `N_Keto_Pure`, `P_Amino_Pure`,
and so on) correspond to these sense-pool quantities. The preprint's
term *sense codons* denotes exactly this 64 − Stop_Count − 1 set
(stop codons and the ATG initiator excluded).

The codon order used for the `Amino_Acids` string follows the standard
NCBI enumeration described in the `ncbi_genetic_code_registry.csv`
section of this README.

Neutron counts for each amino acid are taken from
`amino_acids_nucleons.csv`.

#### Identical N_Pure values in codes 1, 11, and 28

Three translation tables yield the same N_Pure value (3589) and the same
deficit (111). This follows directly from the methodology above.

Code 11 (Bacterial, Archaeal and Plant Plastid) has an amino acid
mapping identical to the Standard Code. Since alternative start codons
are not excluded, its sense codon set matches Code 1.

Code 28 (Condylostoma Nuclear) has three context-dependent stop codons
(TAA, TAG, TGA). Once these are excluded alongside ATG, the resulting
set of included codons becomes identical to the set used in the Standard
Code analysis.

#### Treatment of context-dependent stop codons (transl_table 27, 28, 31)

Three genetic codes use context-dependent decoding, where certain codons
function as amino acids in mid-sequence and as stop signals at the end
of a gene. Two models are evaluated for these codes.

Model 1 (`N_Pure`): codons listed in the `Stop_Codons` column are
excluded from the sense codon set even if they encode an amino acid in
the `Amino_Acids` string. This is the primary model used throughout the
analysis.

Model 2 (`N_Pure_Alt`): context-dependent codons are treated as sense
codons and included, consistent with their elongation capacity. For all
other codes, `N_Pure_Alt` is identical to `N_Pure`.

The same convention applies to the proton-side columns `P_Pure` and `P_Pure_Alt`.

#### Octet I models

In the Standard Code, Octet I consists of 8 fully 4-fold degenerate
codon families (32 codons) with a total nucleon count (protons + neutrons)
of 3700. Since alternative codes may reassign codon meanings, two models
of Octet I are evaluated.

`Octet1_Struct_T` — the total nucleon count (protons + neutrons) of the
32 codons occupying the 8 fixed structural positions of Octet I (codon
families GC, CG, GG, CC, AC, GT, CT, TC), regardless of their amino acid
assignment in the specific code.

`Octet1_Func_T` — the total nucleon count (protons + neutrons) of all
fully 4-fold degenerate codon families present in the specific code,
regardless of their position in the codon table. A codon family is
defined by its first two nucleotides (e.g. GCN); each family consists
of the four codons obtained by varying the third nucleotide (e.g. GCT,
GCC, GCA, GCG). A family is considered 4-fold degenerate if all four of
its codons encode the same amino acid and none is a stop codon.

#### Deficit calculations

Three deficit values are computed to evaluate the stability of the
relationship Octet_T − N_Pure = X across all codes, where Octet_T is
the total nucleon count (protons + neutrons) of Octet I and N_Pure is
the total neutron count of the sense codons excluding the ATG initiator.

`Deficit_vs_3700` — deficit against the theoretical constant 3700,
equal to the Octet I total nucleon count in the Standard Code
(3700 − N_Pure).

`Deficit_vs_Struct` — deficit relative to the structural Octet I total
nucleon count of the specific code (Octet1_Struct_T − N_Pure).

`Deficit_vs_Func` — deficit relative to the functional Octet I total
nucleon count of the specific code (Octet1_Func_T − N_Pure).

The same three deficits are also provided for Model 2 as
`Deficit_vs_3700_Alt`, `Deficit_vs_Struct_Alt`, and
`Deficit_vs_Func_Alt`.

#### Proton residue calculations

Unlike the neutron deficit test described above, the proton
residue test makes no reference to Octet I. It records the
residue of the sense-coding proton pool modulo 37, computed
directly from `P_Pure` (Model 1) or `P_Pure_Alt` (Model 2):

`P_Pure_mod37` = `P_Pure` mod 37
`P_Pure_Alt_mod37` = `P_Pure_Alt` mod 37

For the standard code, `P_Pure_mod37` equals 36, which
corresponds to −1 modulo 37 (the dataset records the
non-negative representative). This residue of −1 is the
parity-induced unit shift discussed in the preprint: the
even-proton property of canonical amino acids forces
|δP(Trp, Ile)| = 36 rather than the lattice multiplier 37,
and the same shift propagates to the global sense pool.

The distribution of `P_Pure_mod37` across NCBI tables
identifies which alternative codes preserve this −1 mod 37
alignment and which do not. As with the neutron deficit test,
results under Model 2 are recorded in `P_Pure_Alt_mod37`.

#### Columns

- `Transl_Table` — NCBI translation table number
- `Code_Name` — full name of the genetic code as given by NCBI
- `Pure_Codons_Count` — number of sense codons excluding the ATG
  initiator, under Model 1 (64 − Stop_Count − 1, where Stop_Count
  includes context-dependent stop codons for transl_table 27, 28,
  and 31)
- `Pure_Codons_Count_Alt` — number of sense codons excluding the ATG
  initiator, under Model 2; identical to `Pure_Codons_Count` for all
  codes except transl_table 27, 28, and 31, where it equals 63
- `N_All` — total neutron count for all 64 codons using the `Amino_Acids`
  string (ncbieaa) from `ncbi_genetic_code_registry.csv`; codons
  explicitly marked as asterisk (*) contribute zero; all other codons
  contribute the neutron count of their corresponding amino acid as
  defined in `amino_acids_nucleons.csv`; for context-dependent codes
  (transl_table 27, 28, 31), codons that function as context-dependent
  stops are represented by their amino acid letter (e.g. 'Q' or 'W')
  and contribute their full neutron count
- `N_Pure` — total neutron count of sense codons excluding the ATG
  initiator (Model 1: context-dependent stop codons excluded)
- `N_Pure_Alt` — total neutron count of sense codons excluding the ATG
  initiator (Model 2: context-dependent stop codons included as sense
  codons); identical to `N_Pure` for all codes except transl_table 27,
  28, and 31
- `Octet1_Struct_T` — total nucleon count (protons + neutrons) of the
  8 fixed structural Octet I families
- `Octet1_Func_T` — total nucleon count (protons + neutrons) of all
  4-fold degenerate families in the specific code
- `Deficit_vs_3700` — deficit evaluated against the constant 3700
  (Model 1)
- `Deficit_vs_Struct` — deficit evaluated against the structural Octet I
  total nucleon count (Model 1)
- `Deficit_vs_Func` — deficit evaluated against the functional Octet I
  total nucleon count (Model 1)
- `Deficit_vs_3700_Alt` — deficit evaluated against the constant 3700
  (Model 2)
- `Deficit_vs_Struct_Alt` — deficit evaluated against the structural
  Octet I total nucleon count (Model 2)
- `Deficit_vs_Func_Alt` — deficit evaluated against the functional Octet

- `P_All` — total proton count for all 64 codons, computed analogously

- `P_Pure` — total proton count of sense codons excluding the ATG
  initiator (Model 1)
- `P_Pure_Alt` — total proton count of sense codons excluding the ATG
  initiator (Model 2); identical to `P_Pure` for all codes except
  transl_table 27, 28, and 31
- `P_Pure_mod37` — residue of `P_Pure` modulo 37; for the standard code
  this is 36 ≡ −1 (mod 37), a parity-induced deficit of one proton on
  the 37-lattice. The deficit is a consequence of the parity property
  of the canonical amino acids — every canonical amino acid has an
  even proton count — which forces the localizing pair Trp/Ile to give
  |δP| = 36 instead of 37. The distribution of this residue across
  NCBI tables shows which alternative codes preserve this −1 mod-37
  alignment and which do not.
- `P_Pure_Alt_mod37` — residue of `P_Pure_Alt` modulo 37 (Model 2);
  identical to `P_Pure_mod37` for all codes except transl_table 27, 28,

### keto_amino_balance_models.csv

This dataset reports the keto/amino partition of the sense pool across all genetic code variants recognized by NCBI (27 translation tables, numbered 1–33, with gaps), in both neutron and proton quantities, under the same two sense-pool models as `deficit_models_analysis.csv`.

The third codon position partitions all 64 codons into two halves of
32 codons each: the `Keto` half (third position is G or T) and the
`Amino` half (third position is A or C). For each NCBI table, the
total neutron and proton counts of each half are computed over the
sense pool only — service codons are excluded from both sums. Under
Model 1, the excluded service codons are all codons listed in the
`Stop_Codons` column plus the ATG initiator; under Model 2, only
unconditional stop codons — those marked `*` in the `Amino_Acids`
string — are excluded alongside the ATG initiator, so that
context-dependent codons return to the pool. The two models coincide
for every table that declares no context-dependent stop. This is the
same exclusion convention used in `deficit_models_analysis.csv`. In
the present registry all three context-dependent tables (27, 28, 31)
declare no unconditional stop at all, so Model 2 excludes only ATG for
them; deriving the set from the `*` markers rather than from a
per-table flag keeps the convention well defined should a future table
declare both kinds at once.

For the standard code, the sense-pool keto/amino differences are
N_Keto − N_Amino = 37 and P_Keto − P_Amino = 36. Across the NCBI tables, this signature partitions the codes into those that preserve
the (37, 36) signature and those that perturb it.

#### Columns

- `Transl_Table` — NCBI translation table identifier (1..33, with gaps)
- `Code_Name` — full name of the genetic code variant
- `N_Keto_Pure` — total neutron count of sense codons in the Keto half
  (third position G or T) under Model 1
- `N_Amino_Pure` — total neutron count of sense codons in the Amino half
  (third position A or C) under Model 1
- `N_Diff_Pure` — `N_Keto_Pure − N_Amino_Pure` (Model 1)
- `P_Keto_Pure` — total proton count of sense codons in the Keto half
  under Model 1
- `P_Amino_Pure` — total proton count of sense codons in the Amino half
  under Model 1
- `P_Diff_Pure` — `P_Keto_Pure − P_Amino_Pure` (Model 1)
- `N_Keto_Pure_Alt`, `N_Amino_Pure_Alt`, `N_Diff_Pure_Alt`,
  `P_Keto_Pure_Alt`, `P_Amino_Pure_Alt`, `P_Diff_Pure_Alt` — the
  corresponding quantities under Model 2; identical to the Model 1
  versions for all codes except transl_table 27, 28, and 31

### service_codon_balance_comparison.csv

This dataset determines minimal formal assignments to the service
codons of each table and pool model. For each of P and N separately,
it compensates the difference between the third-position Keto/Amino
halves. Assignments are computed under balance alone and with the
additional requirement that the global sums be divisible by 37.
The 27 tables and two models produce 54 rows, one per table–model
combination. The number of service positions is the selected model's
stop-position count plus the ATG position.

#### The two procedures

For each quantity `Q` in {P, N} independently, write `Q_pool` for the
service-excluded pool total of the table under the model in question,
`d_Q` for `Q_pool(Keto) − Q_pool(Amino)`, and `s_K`, `s_A` for the
numbers of stop positions falling in the Keto and Amino branches, with
`S = s_K + s_A`. Let `y` be the shared value of `Q` carried by every
stop codon and `x` the separate value carried by ATG, which lies in the
Keto branch. Balancing the two halves requires

    d_Q + s_K*y + x − s_A*y = 0,     hence   x = (s_A − s_K)*y − d_Q

and the quantity minimised is the total added contribution

    C_Q = S*y + x = 2*s_A*y − d_Q.

The `Bal_` columns report the minimal solution under balance,
non-negativity and integrality alone. The `Mod_` columns report the
minimal solution when `(Q_pool + C_Q) % 37 == 0` is imposed as well.
Proton and neutron components are solved independently. Equality
between proton and neutron stop parameters and specific ATG parameter
values are not prescribed.

#### Statuses

Solvability differs between the two quantities, so each is given its
own status:

- `unique` — a single minimal assignment of the existing parameters;
- `total_only` — several minimal assignments sharing one total
  contribution and one resulting sum. Assignment cells are left empty
  so that no arbitrary representative is presented as the solution;
- `none` — no admissible solution exists.

An empty numeric cell always means "not defined"; zero is never used to
denote absence. If the selected model has no stop positions, the stop
parameter does not exist and its field remains empty. The ATG parameter
is filled only when the corresponding component and procedure have
a solution. Boolean columns are left empty rather than set to
`False` when the underlying result is undefined.

#### Reading the standard code

Under Model 1 the standard code gives, for the balance alone,
`(P, N) = (36, 37)` to each stop codon and `(0, 0)` to ATG, producing
`P = 4288` and `N = 3700`. The neutron total is already divisible by 37
and already equal to the nucleon sum of the code's own structural
Octet I, although neither was required. Imposing divisibility raises the
assignment to `(37, 37)` and `(1, 0)`, producing `P = 4292`: four
protons and no neutrons, that is one proton added to each of the four
service codons. The `Cost_P` and `Cost_N` columns record exactly this
difference.

#### Columns

- `Transl_Table` — NCBI translation table identifier (1..33, with gaps)
- `Code_Name` — full name of the genetic code variant
- `Model` — service-excluded pool model, 1 or 2
- `Stop_Count` — number of stop positions treated as service codons
  under this model
- `Stops_Keto`, `Stops_Amino` — how those positions divide between the
  branches (third position G or T, versus A or C)
- `Octet1_Struct_T` — nucleon sum of the eight structural Octet I
  families under this table's amino acid assignments

For each procedure, with the prefix `Bal_` (balance only) or `Mod_`
(balance and divisibility):

- `Stop_P`, `Stop_N` — value carried by each stop codon
- `Start_P`, `Start_N` — value carried by ATG
- `Added_P`, `Added_N` — total added contribution `C_Q`
- `P_All`, `N_All` — resulting totals for the full 64-codon table
- `Status_P`, `Status_N` — `unique`, `total_only` or `none`
- `N_Diff_Octet1_Struct` — `N_All − Octet1_Struct_T`
- `N_All_eq_Octet1_Struct` — whether that difference is zero

Remaining columns:

- `Bal_P_Divisible37`, `Bal_N_Divisible37` — whether the total reached
  under the balance alone is divisible by 37, that is, whether
  divisibility arises without being imposed
- `Cost_P`, `Cost_N` — `Mod_Added_Q − Bal_Added_Q`, filled only where
  both procedures are solvable
- `Mod_Stop_Params_Equal` — whether the proton and neutron stop parameters
  coincide under the divisibility procedure; computed only where stop positions
  exist and both components are uniquely determined

The pool halves themselves are not duplicated here. They are the
columns of `keto_amino_balance_models.csv`: `N_Keto_Pure`,
`N_Amino_Pure`, `P_Keto_Pure`, `P_Amino_Pure` for Model 1 and the
`_Alt` variants for Model 2. The two datasets are intended to be read
together.

The prefix `Mod` names the procedure that imposes divisibility; it does
not imply that any solution it returns is the Key 1 assignment of the
standard code.

### Pool60 group datasets

The four `pool60_*` files describe the same 33 groups as the Key 0/Key 1
files after removing ATG, TAA, TAG, and TGA from every group:

- `pool60_nucleon-data.csv` contains `T`, `P`, `N`, and `Delta_P_N`;
- `pool60_divisibility-37.csv` contains their `q*37+r` expressions;
- `pool60_equalities.csv` enumerates equalities between group quantities;
- `pool60_ratios.csv` contains six exact reduced ratios and their decimal
  approximations.

Their column schemas and sorting rules match the corresponding Key 0/Key 1
files documented below. The essential difference is `Group_Size`, which is
recomputed after the four service codons are excluded. These files do not use
`key_parameters.csv` when calculating group totals and are therefore
independent of the selected key.

### key0_nucleon-data.csv and key1_nucleon-data.csv

This description applies to both files. Both files share an identical
column structure; nucleon values differ across files due to different
start and stop codon assignments specified by each key.

This dataset reports the fundamental nucleon composition of the 33 codon
groups defined in `codon_groups.csv`, computed under the parameter
configuration of the corresponding key.

#### Computation

Each row corresponds to one codon group. Nucleon values are computed by
iterating over all codons in the group, retrieving the strictly defined
parameters of the encoded amino acid's empirical formula for each codon,
and summing the results across the group.

The contribution of the start codon (ATG) and stop codons (TAA, TAG, TGA)
is determined by the active key. In the reference configuration (key0),
stop codons contribute zero to all nucleon quantities. Alternative keys
(e.g., key1) assign specific non-zero parameter values to start and/or
stop codons; these configurations are explicitly defined in the study.

#### Nucleon quantities

Four strict, structurally independent nucleon quantities are reported
for each group:

`Total_Nucleons` — total nucleon count, defined as:

T = P + N

where P is the total proton count (sum of atomic numbers of all atoms)
and N is the total neutron count (computed for the most abundant stable
isotopes of each element).

`Delta_P_N` — proton–neutron difference:

Δ = P − N

This value is numerically equal to the number of hydrogen atoms in the
molecular composition, as hydrogen is the only element in amino acid
molecules for which the neutron count is zero.

#### Columns

- `Group_Name` — descriptive name of the codon group
- `Group_ID` — unique integer identifier of the codon group
- `Twin_Group_ID` — identifier of the twin group sharing identical amino
  acid composition, or empty string if no twin exists
- `Code_Section` — partition of the genetic code to which the group
  belongs: "All code" (Group_ID 1–11), "Octet I" (Group_ID 12–22),
  or "Octet II" (Group_ID 23–33)
- `Group_Size` — number of codons in the group
- `Total_Nucleons` — total nucleon count (P + N)
- `Protons` — total proton count (P)
- `Neutrons` — total neutron count (N)
- `Delta_P_N` — proton–neutron difference (P − N)

### key0_divisibility-37.csv and key1_divisibility-37.csv

This description applies to both files. Both files share an identical
column structure; values differ across files due to different start and
stop codon assignments specified by each key.

This dataset reports the divisibility by 37 of the four fundamental
nucleon quantities for each of the 33 codon groups. The source values
are taken directly from the corresponding `_nucleon-data.csv` file for
the same key.

#### Purpose

The dataset makes the divisibility structure of nucleon quantities
immediately visible without requiring additional arithmetic. Rather than
storing raw integer values (which are already present in the
`_nucleon-data.csv` files), each cell encodes the result of Euclidean
division by 37, allowing the reader to identify exact divisibility and
remainder at a glance.

#### Expression format

Each cell contains a string expression of one of the following forms:

- `q*37` — if the value is exactly divisible by 37, where q is the
  integer quotient
- `q*37+r` — if the value is positive and not exactly divisible by 37,
  where q is the integer quotient and r is the remainder (1 ≤ r ≤ 36)

Exceptions to this format:

- Positive values less than 37 are recorded as plain integers.
- All negative values are recorded as plain integers to avoid the
  ambiguity of modulo operations on negative numbers across different
  programming languages.

The original nucleon value can be recovered from any expression by
evaluating it arithmetically.

#### Columns

- `Group_Name` — descriptive name of the codon group
- `Group_ID` — unique integer identifier of the codon group
- `Twin_Group_ID` — identifier of the twin group sharing identical amino
  acid composition, or empty string if no twin exists
- `Code_Section` — partition of the genetic code to which the group
  belongs: "All code" (Group_ID 1–11), "Octet I" (Group_ID 12–22),
  or "Octet II" (Group_ID 23–33)
- `Group_Size` — number of codons in the group
- `Total_mod37` — divisibility expression for total nucleon count
- `Protons_mod37` — divisibility expression for proton count
- `Neutrons_mod37` — divisibility expression for neutron count
- `Delta_mod37` — divisibility expression for proton–neutron difference

### key0_equalities.csv and key1_equalities.csv

This description applies to both files. Both files share an identical
column structure; the set of recorded equalities differs across files
due to different start and stop codon assignments specified by each key.

This dataset records all observed numerical equalities between nucleon
quantities across codon groups, under the parameter configuration of the
corresponding key. Each row represents one equality: a single numerical
value shared by a source quantity and a target quantity belonging to two
(possibly distinct) codon groups. A group may appear as both source and
target in the same row when a quantity of a group equals a different
quantity of the same group.

#### Match types

The column `Match_Type` classifies each equality by the relationship
between the compared parameters:

- DIFF_PARAM — the source and target groups are of different
  sizes (different levels), regardless of whether the two
  nucleon quantities involved are of the same type or of
  different types (e.g., Neutrons of a size-32 group equals
  Total_Nucleons of a size-16 group).
- CROSS_PARAM — the source and target groups are of the same
  size, and the two sides involve different nucleon quantities
  (e.g., Protons of group A equals Neutrons of group B, where
  A and B have the same Group_Size).
- SAME_PARAM — the source and target groups are of the same
  size, and both sides involve the same nucleon quantity
  (e.g., Protons of group A equals Protons of group B).

#### Directionality

Source and target reflect the algorithmic traversal order used by the
program when scanning group pairs. This ordering is not based on
Group_ID magnitude and does not imply a directional or causal
relationship between source and target.

#### Columns

- `Nucleon_Value` — the shared numerical value of the equality
- `Match_Type` — classification of the equality: `SAME_PARAM`,
  `CROSS_PARAM`, or `DIFF_PARAM`
- `Source_Section` — code section of the source group
- `Source_ID` — integer identifier of the source group
- `Source_Name` — descriptive name of the source group
- `Source_Parameter` — nucleon quantity of the source
- `Target_Parameter` — nucleon quantity of the target
- `Target_Name` — descriptive name of the target group
- `Target_ID` — integer identifier of the target group
- `Target_Section` — code section of the target group

### key0_ratios.csv and key1_ratios.csv

This description applies to both files. Both files share an identical
column structure; values differ across files due to different start and
stop codon assignments specified by each key.

This dataset reports pairwise ratios of the four fundamental nucleon
quantities for each of the 33 codon groups. The source values are taken
directly from the corresponding `_nucleon-data.csv` file for the same key.

#### Quantities and notation

The four nucleon quantities are abbreviated as follows throughout the
column names:

- T — Total_Nucleons
- P — Protons
- N — Neutrons
- Delta — Delta_P_N

The dataset reports 6 ratios, covering every unordered pair of the four
quantities exactly once. For each pair, the direction of division is
fixed by the definitions above (e.g., P/T is reported, not T/P).

#### Dual representation

For each ratio, two representations are provided in adjacent columns:

`_Rational` columns contain the exact value as a fully reduced fraction
string of the form `"p/q"`, where p and q are coprime integers. This
representation is exact and lossless.

`_Ratio` columns contain the decimal approximation of the corresponding
fraction, rounded to four decimal places.

#### Columns

- `Group_Name` — descriptive name of the codon group
- `Group_ID` — unique integer identifier of the codon group
- `Twin_Group_ID` — identifier of the twin group sharing identical amino
  acid composition, or empty string if no twin exists
- `Code_Section` — partition of the genetic code to which the group
  belongs: "All code" (Group_ID 1–11), "Octet I" (Group_ID 12–22),
  or "Octet II" (Group_ID 23–33)
- `Group_Size` — number of codons in the group
- `P_T_Rational`, `P_T_Ratio` — Protons / Total_Nucleons
- `N_T_Rational`, `N_T_Ratio` — Neutrons / Total_Nucleons
- `Delta_T_Rational`, `Delta_T_Ratio` — Delta_P_N / Total_Nucleons
- `P_N_Rational`, `P_N_Ratio` — Protons / Neutrons
- `Delta_P_Rational`, `Delta_P_Ratio` — Delta_P_N / Protons
- `Delta_N_Rational`, `Delta_N_Ratio` — Delta_P_N / Neutrons


### position_axis_analysis.csv

Output of `controls.py` (not part of the `reproduce.py` pipeline). The three
chemical axes (Keto/Amino, Strong/Weak, Purine/Pyrimidine) are applied to the
first, second, and third codon position in turn, under the service-excluded
pool, Key 0, and Key 1, giving 3 positions × 6 axis groups × 3 counting modes
= 54 rows. The four `*_mod37` columns give each nucleon quantity reduced
modulo 37, so that a value of 0 marks divisibility by 37.

#### Columns

- `Position` — codon position at which the axis is applied (1, 2, or 3)
- `Axis` — name of the axis group: Keto, Amino, Strong, Weak, Purine, or
  Pyrimidine
- `Members` — the two nucleotides defining the group at that position
  (e.g. `{G, T}`)
- `Pool` — counting mode: `sense` (legacy machine name: ATG, TAA, TAG, and
  TGA excluded), `key0` (service codons at their Key 0 values: stop codons
  (0,0), ATG with methionine counts), or `key1` (service codons at their
  Key 1 values)
- `Group_Size` — number of codons counted in the group under that mode
- `Total_Nucleons`, `Protons`, `Neutrons`, `Delta_P_N` — the four nucleon
  quantities summed over the group
- `Total_mod37`, `Protons_mod37`, `Neutrons_mod37`, `Delta_mod37` — the same
  quantities reduced modulo 37 (0 means divisible by 37)

### prime_divisibility_scan.csv

Output of `controls.py`: 25 primes up to 97 × 3 sets = 75 rows.
Each set is counted over all T/P/N/Δ instances and distinct nonzero values.
`param_independent` contains the 17 complete groups with no service codon;
`key0` and `key1` contain all 33 groups under the respective key.
The ratio `Divisible_Distinct / Expected_Distinct` is pk/m, where
m=`Total_Distinct` and k=`Divisible_Distinct`. This descriptive comparison
with the 1/p benchmark is not a p-value: its range is bounded by p and its
step is p/m. Duplicates and algebraic dependencies need separate treatment.
Prime powers impose additional divisibility conditions and are outside the
scan. Absence of multiples of 37² in these sets was checked separately.

#### Columns

- `Value_Set` — `param_independent`, `key0`, or `key1`
- `Prime` — the prime tested
- `Divisible_All` — number of group quantities (counting every group instance)
  divisible by the prime
- `Total_All` — total number of group quantities in the value set
- `Divisible_Distinct` — number of distinct nonzero quantity values divisible by
  the prime
- `Total_Distinct` — total number of distinct nonzero quantity values
- `Expected_Distinct` — `Total_Distinct / Prime`, an exact reduced fraction
  for the uniform-residue benchmark, not an expectation over random codes
- `Divisible_Distinct_OddCores` — number of distinct odd cores among
  divisible values after all factors of 2 are removed. Copies v, 2v, 4v
  collapse; independence of the remaining quantities is not established.
  Under Key 0, 37 has ten cores; 73 and 61 have one each: 73 and 549.

### position_asymmetry_ncbi.csv

Output of `controls.py` (not part of the `reproduce.py` pipeline). For each of
the 27 NCBI translation tables, the Keto/Amino functional-group axis
(`{G, T}` versus `{A, C}`) asymmetry in the service-excluded pool — the value
on the Keto side minus the value on the Amino side — is computed for all four
nucleon quantities at each of the three codon positions under two parallel
pool models. Model 1
excludes ATG and every codon listed in the table's `Stop_Codons` field,
including context-dependent stops. Model 2 excludes ATG and only positions
marked `*` in `Amino_Acids`, thereby returning context-dependent stop codons to
the pool with their amino-acid assignments. The models differ only for Tables
27, 28, and 31 in the fixed registry snapshot. Thus 27 tables × 2 models ×
3 positions = 162 rows.

Under Model 1, the full three-position signature occurs for Tables 1, 11, and
28; under Model 2 it occurs for Tables 1 and 11. Table 28 is not an independent
replication under Model 1, because exclusion of its three context-dependent
stops makes its analyzed pool identical to that of the standard code. No table
with a non-equivalent analyzed pool reaches all three positions in either
model. Since the NCBI tables are evolutionarily related rather than independent
samples, this documents specificity among natural codes rather than
improbability under a null model.

The N/T/N pattern across positions was selected post hoc.
`Position_Has_Div37` and `Positions_With_Div37` have a broader definition:
they count divisibility of at least one of the four differences. They do
not encode the specific N/T/N sequence. In this registry, the two conditions
give the same list of tables passing all three positions.

#### Columns

- `Transl_Table` — NCBI translation table number
- `Code_Name` — NCBI name of the translation table
- `Pool_Model` — service-excluded-pool convention (`Model_1` or `Model_2`)
- `Position` — codon position (1, 2, or 3)
- `Keto_minus_Amino_T`, `Keto_minus_Amino_P`, `Keto_minus_Amino_N`,
  `Keto_minus_Amino_Delta` — the Keto-minus-Amino asymmetry for the total
  nucleon, proton, neutron, and proton–neutron-difference quantities
- `T_mod37`, `P_mod37`, `N_mod37`, `Delta_mod37` — the same asymmetries reduced
  modulo 37 (0 means divisible by 37)
- `Position_Has_Div37` — 1 if at least one of the four asymmetries at this
  position is divisible by 37, else 0
- `Positions_With_Div37` — for this table and pool model, the number of codon
  positions (0–3) at which at least one asymmetry is divisible by 37; filtering
  on the value 3 selects Tables 1, 11, and 28 under Model 1 and Tables 1 and 11
  under Model 2

### representation_sensitivity.csv

Output of `controls.py`: 13 quantities × 3 representations = 39 rows.
The neutral free amino acid is the baseline; the peptide model subtracts
one water (10 protons, 8 neutrons) from each molecular formula; the zwitterion
has the same atoms as the baseline. These are uniform shifts (ΔP, ΔN).
They preserve the molecular tryptophan–isoleucine differences and the
third-position Keto/Amino and Strong/Weak differences, whose groups each
contain 30 codons. The conclusion concerns the tested shifts, not arbitrary
molecular representations.

Absolute values change in the peptide model: pool N is 3109 ≡ 1 and P is
3580 ≡ 28 (mod 37). The Octet I nucleon sum minus the pool neutron sum in
that same representation is 3124−3109=15. In all three representations,
tryptophan–isoleucine differences remain 37 in N and 36 in P. The zwitterion
also preserves all absolute values; these are therefore not preserved only
by the neutral free form. For the full neutron sum, divisibility survives
when 60·ΔN ≡ 0 (mod 37), equivalent to ΔN ≡ 0 (mod 37).
The original proton sum 4180 is itself not divisible by 37.
Before writing the file, the script checks baseline N=3589, P=4180,
deficit=111, and the molecular differences 37/36.

The machine names `N_sense`, `P_sense`, and
`deficit_T_OctetI_minus_N_sense` refer to the service-excluded 60-codon pool.
They are retained for compatibility.

#### Columns

- `Representation` — the molecular representation (`free`, `peptide_residue`, `zwitterion`)
- `Delta_P`, `Delta_N` — the per-residue proton and neutron offset from the free amino acid
- `Anchor` — the quantity computed (e.g. `N_sense`, `dN_Trp_Ile`, `KetoAmino_dN`)
- `Class` — `absolute` (a sum or deficit that changes under a shift) or `relational` (a tested molecular or equal-size-group difference preserved under uniform shifts)
- `Value` — the integer value of the anchor under this representation
- `Value_mod37` — the value reduced modulo 37 (0 means divisible by 37)
- `Matches_Free` — whether this equals the free-amino-acid value; True for every relational anchor and every zwitterion anchor, False for the absolute peptide-residue anchors

### mc_significance.csv

Output of `mc_significance.py` (a seeded Monte Carlo, not part of the
`reproduce.py` pipeline). One row for each of the six statistical summaries
S1, S2, S3, S4sense, S4a, and S4b, recording the standard code's observed
value, the null mean, the tail count, the p estimate, and its Monte Carlo
uncertainty interval. 6 rows.

#### Columns

- `Statistic` — `S1`, `S2`, `S3`, `S4sense`, `S4a`, or `S4b`
- `Description` — what the statistic counts
- `Tail` — tail direction: an event for S1, `>=` for S2/S3, or `<=` for
  the three mean-distance statistics
- `Observed` — the standard code's numerical value
- `Null_Mean` — mean of the statistic over the random codes (for S1, the
  divisible fraction)
- `Tail_Count` — number of random codes at least as extreme as the standard code
- `P_MC` — tail-probability estimate
  `(Tail_Count + 1) / (N_Trials + 1)`
- `CI_Low`, `CI_High` — lower and upper bounds of the 95% Monte Carlo
  uncertainty interval
- `N_Trials` — number of random codes drawn
- `Seed` — random seed used (fixed, for reproducibility)

### mc_sensitivity.csv

Output of `mc_sensitivity.py`: six rows, three statistics in two models.
This is a supplementary exploratory analysis, separate from
`mc_significance.csv` and the deterministic pipeline.

- `Null_Model` — `relabel20` or `fixed_atg_met19`.
- `Statistic` — `S2`, `S4sense` or `S4pos`.
- `Tail` — `>=` for S2, `<=` for both mean-distance statistics.
- `Observed` — the standard code's value.
- `Null_Mean` — the mean statistic across random codes, weighting each code equally.
- `Null_SD` — the sample standard deviation across random codes (divisor M−1).
- `Tail_Count` — the number of tail hits.
- `P_MC` — `(Tail_Count+1)/(N_Trials+1)`.
- `CI_Low`, `CI_High` — the 95% Wilson interval for `Tail_Count/N_Trials`.
- `N_Trials`, `Seed` — the number of trials and the random seed.
- `Observed_Positive_Count` — the number of positive distances in the standard set of 132 (104); a diagnostic for the whole set, repeated for all three statistics.
- `All_Zero_Trials` — the number of random codes with all 132 distances zero; also repeated within a model.
